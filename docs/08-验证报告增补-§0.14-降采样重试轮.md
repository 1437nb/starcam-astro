# 验证报告增补 §0.14 — 降采样重试轮落进 App（2026-08-28）

> 可直接粘贴进 `StarRecognizer\docs\验证报告.md`。

## 背景

服务器实测结论（§0.12/§0.13）：12 张真实手机照片中，变焦拍摄的 5057（41° 视场）
在原始分辨率下官方引擎解不出，加 `--downsample 2` 后 log-odds 248 解出——
大星点 + 噪声在提星阶段污染 quad 匹配，降采样后星点归一、匹配更稳。
另外两处"服务器结论"核实后**无需改动**：
- `--depth 400`：solve-field 默认 depth 仅 10→200 递进（engine-main.c 默认值），
  App 的 JNI 路径（astro_bridge.c 直接用 simplexy 全部星点建 quad）天然等效
  depth=∞，已优于 400 → **.so 不动**；
- `--scale-low 40 --scale-high 100`：App 盲解段 2 本就是 40°~120° → 已覆盖。

## 改动（纯 Kotlin，未动 .so）

`StarSolver.kt`：
1. `downsampleRetryPlan(fovDeg, longEdgePx)`：仅"无视场先验盲解 + 图像长边 >1200px"
   时返回（1100px 长边, 原分段）重试计划；有 EXIF 焦距先验的路径不触发。
2. `rescaleSolveFor(solve, fromW, fromH, toW, toH)`：降采样图定标结果换算回原图
   坐标系——crpix 按放大比例外推、CD 与 pixscale 按缩小比例换算（中心对齐，
   cd21 等符号关系不变）、fieldRadiusArcmin 重算，供原图叠加渲染。
   换算正确性已由单测覆盖（crpix/CD/pixscale/半径逐项断言）。
3. `solve()` 官方引擎分支新增第 3 轮：盲解全段失败后，把 ≤2200px 图再降至
   1100px 长边重试原分段，每段限时 `NATIVE_DOWNSAMPLE_RETRY_TIME=10s`，
   成功后进度文案显示"降采样重试"。
