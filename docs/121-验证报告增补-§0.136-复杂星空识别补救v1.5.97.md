# §0.136 复杂星空识别补救（v1.5.97，未发布）

## 范围

开发者反馈银河/星云密场、光污染/薄云/地景、暗星/拖线/虚焦/噪声环境的识别成功率偏低。本轮先增加可回归的补救路径，保留原有引擎、星表与正常成功路径。

- `AdaptiveStarDetector.kt`：64 像素网格估计背景中位数及相邻像素差的稳健噪声，再插值到图像；平滑后找局部峰，用局部环背景、核心通量占比与二阶矩剔除弥散斑、单像素热像素和过长细线。保留轻微拖线，不将严重虚焦或长拖线宣传为已解决。
- 备用检测最多输出 64 个星点，候选元数据上限为输出数的 32 倍。原图只读，不将识别预处理写回图片或标注导出。
- `LocalStarMatcher` 支持原路径失败后惰性调用一次补救；原主表不足 5 颗时也可以补救。生产 `LocalMatcherStep` 给原主表/SEP/深域搜索分配进入匹配阶段时剩余预算的 60%，为独立检测保留余量；原路径正常成功时不运行新检测器，时间片耗尽则转补救。总预算不增加，较慢的原路径会较早切换搜索。
- 补救包含检测和匹配，独立上限 30 秒，并继承全局取消/时间预算；原有路径耗时另计。全局预算已耗尽时不会额外续时。
- 已知输入视场小于 10° 时不启动额外补救，也不预留其预算，遵守既定手机星空产品范围；原有求解能力不受此限制。允许深域且可信视场 ≤20° 时，补救优先尝试深域，避免先重复全部浅域阶梯；更宽或未知视场仍浅域优先。可信视场仅用于备用评分候选预筛和最终一致性把关，不从失败候选推断视场。
- 所有原有几何/对齐率门槛保留；补救另要求至少 10 颗匹配内点，且有可信输入视场时必须落在既有 `FovEstimate.fovRange()` 范围内。未提高星点上限或降低匹配门槛来换取解出数量。
- `LocalMatcherStep` 接入上述生产路径，增加中英文进度和结果来源说明，日志中记录补救是否命中，成功时保存实际使用的星点与本次诊断。
- 修复实际模拟器复现的失败诊断异常：可选原生库不可用、类初始化失败时，`dumpLocalFail()` 的 `LinkageError` 不再把普通未识别结果变成异常。

局部背景/噪声与源检测分开的设计可参阅 [SEP 官方教程](https://sep.readthedocs.io/en/stable/tutorial.html)。本轮备用检测为 Kotlin 实现，不引入 Python/SEP 运行时，不修改 C 桥或随包原生库。

`AdaptiveStarDetectorTest` 不依赖私人素材，CI 正常执行。`AdaptiveFieldProbeTest` 依赖本机 `testdata/`，完整回归必须执行；仅在 CI 的 `-PskipPhotoTests=true` 模式排除，素材缺失直接失败。

32 场对照使用与旧观察台一致的 64 星点上限，并提供来自 FITS 元数据的可信视场；调用同一个匹配入口，原有搜索先执行，`usedRecovery=false` 的正确成功计入基线，再计入补救新增的正确结果。生产上限 100 由 cyg15 单项另行验证；生产预算调度由 Android 实际步骤用例验证。原有成功入口的惰性行为另有断言，避免重复执行昂贵的整条搜索。素材含小于产品目标 10° 的观察场，不能把整体比例当作用户照片成功率。

在 `C:\starcam\code` 下，测试与 APK 构建必须分开串行执行：

```powershell
.\gradlew.bat :app:cleanTestDebugUnitTest :app:testDebugUnitTest --no-build-cache --offline --console=plain
.\gradlew.bat :app:assembleDebug --offline --console=plain
.\gradlew.bat :app:assembleDebugAndroidTest --offline --console=plain
.\gradlew.bat '-Dorg.gradle.jvmargs=-Xmx3g -XX:MaxMetaspaceSize=768m' --max-workers=1 '-Pandroid.lint.useK2Uast=false' :app:lintDebug -x :app:lintAnalyzeDebugAndroidTest -x :app:lintAnalyzeDebugUnitTest --offline --console=plain
```

在 `C:\starcam` 下，用已启动的模拟器执行功能验收（不清理应用数据）：

```powershell
python tools/android_acceptance.py --serial emulator-5554 --install
python tools/android_acceptance.py --serial emulator-5556 --install
```

本轮默认 ADB 5037 服务启动失败，使用本机独立端口 5038；启动模拟器及验收脚本前设置 `$env:ADB_SERVER_SOCKET='tcp:127.0.0.1:5038'` 与 `$env:ANDROID_ADB_SERVER_PORT='5038'`。这是本机测试环境设置，不进入 App。

## 仍有边界

- 本轮是局部、可量化的改进，不宣称所有复杂环境均能识别；首轮仍有 19/32 未解出。
- 严重虚焦、长拖线、厚云遮挡、可用星数太少、地景点光源主导，以及镜头畸变仍可能失败。
- arm64 真机与开发者此次实际失败照片尚未复测；模拟器不代替真机。没有修改官方原生引擎的检测或索引能力。
- 本轮只交付 Debug 与验证记录，不构建 Release，不推送或发布 GitHub。

## 手工验收

1. 导入一张已知天区的复杂星空照片，主路径未解出时应出现「复杂星空补救」进度；总耗时仍遵守设置中的预算，成功结果注明补救来源。
2. 按实际亮星位置检查星座连线落点、中心坐标及视场，不能只凭「识别成功」或星点数判定正确。
3. 正常清晰照片仍应直接解出，无须进入补救；原图/预览尺寸导出应与此前一致。
4. 导入纯黑/无星画面，应正常显示失败，不因设备缺少原生库而异常退出。
5. 补救中取消/返回，再导入另一张，旧任务应停止，不覆盖新任务的进度或结果。
