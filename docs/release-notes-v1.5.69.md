# StarCam v1.5.69 更新说明

**主题：按外部代码走查报告做的三批加固 —— 正确性、隐私、性能**

外部对 v1.5.63 做了一次全量代码走查（87 个 Kotlin 文件、约 3.2 万行），列出 30 项
（严重 11 / 中等 11 / 轻微 8）。这一版把其中**能本地验证、且风险可控**的部分做完了，
并把"哪些做了、哪些没做、为什么"逐条写进 `docs/81`。

> 说明：走查基于 v1.5.63，而本版之前的树已经领先若干修复批次，所以第一步是**逐条核对现状**
> 再动手 —— 核对发现只有一项被既有修复覆盖了一半，其余严重项都仍然存在。

## 修复与加固

### 1. 跨赤经接缝的候选验证（正确性）

候选验证的切平面投影中心原用**算术平均** `(RA_A+RA_B+RA_C)/3`。天区跨 0°/360° 时这个
平均值会落到天区对面（例如 359.5° 与 0.9°），投影完全错位，该候选的"第 4 星验证"必然
失败。已改用球面平均（同文件的另一处早就改过，这里是漏改）。

**顺带说明影响面**：我们实测了 12 个赤经中心 × 4 档视场（关掉打分轮，让投票轮单独工作），
**跨接缝的视场全部照常解出** —— 因为验证是逐个候选三角形做的，只丢"跨接缝的那些"，
不跨接缝的候选不受影响。所以它是一处真实但影响有限的缺陷，而不是报告描述的"该天区零产出"。
新增了一个不依赖外部素材的**接缝回归测试**，CI 中照常执行。

### 2. 识别历史与统计不再静默丢数据（正确性）

历史与统计都是"读 → 改 → 写回"，而写方有两条线程路径（单张识别在主线程、批量识别在
IO 线程）。并发时后写覆盖先写，条目会无声消失。四条写路径已统一加互斥。

### 3. 结果页不再阻塞主线程（流畅度）

识别结束后写统计（整份 JSON 重写）、写历史、以及"最近星座"（要遍历全星表算角距）原本都
在主线程做；修复后的版本还会读取 EXIF 与**阻塞式定位**。这些现在全部移到 IO 线程，
主线程只剩一次界面状态更新。

### 4. API Key 的明文降级会明确提示（隐私）

加密存储初始化失败时会回退普通存储（这是刻意的可用性取舍），但此前只在日志里留一行，
**用户完全无感知** —— 可计费的 API Key 在降级设备上以明文落盘。现在设置页会显示红色警示，
中英双语。同版新增**原生引擎可用性上报**：本机只有 arm64 原生库，32 位等设备上官方引擎
与弱星提星整体不可用，现在设置页会直接写出来（此前静默降级，用户与支持者都看不到）。

### 5. 原生层入参校验（健壮性）

JNI 边界补了四道校验：外部星点数组按**调用方给出的长度**校验后再读（原先只信数组内容里的
计数，数组被截断即越界读）；拒绝空路径（原先会走到 `strcmp(NULL)` 直接段错误）；
字符串复制失败时整体放弃而不是留下空槽位；路径拷贝显式补终止符。原生层崩溃没有 Java 堆栈、
线上极难排查，这几道正是为它加的。

### 6. 热路径内存治理（性能）

- 投票轮原先**每轮**重建一份 8419 项星表索引，而等价的索引早已惰性缓存 —— 改为直接复用；
- 线程池原先每轮"建完即销毁"（一次识别最多 6 轮）—— 改为复用；
- 亮源掩码原先每次检测都分配整幅前缀和图（2200px 照片约 **14.5MB + 1650 个小对象**，
  而绝大多数场景掩码为空）—— 改为滑动窗口求和，内存降到与一行像素同量级、零大对象分配。

> 掩码这处带来一个**可见的行为差异**：新实现的窗口均值精度更高，掩码边界因此有微小位移，
> 演示照片 5087 的内点数由 25 变为 14（天区、视场、判定都不变，仍是正确解）。
> 该细节记在 `docs/81` §7.1。

### 7. 测试引擎移出正式包（工程）

含"下载远程内容并执行"链路的自测入口原在正式源码集里，只靠 R8 裁剪兜底。现已整体移入
`src/debug` 源集（release 侧无任何引用，已核实两个变体均可编译）。

## 验证

- 全量单元测试 **190 项 0 失败**（CI 侧运行 **175 项** —— 跳过 8 个依赖不入库实拍素材的
  测试类，并另跑一遍 gitleaks 凭据扫描）。
- 12 张真实照片回归 **12/12 正确解出、0 假阳性**；假阳性对照
  （apod3 / apod5 / pleiades 必须保持未解出）全部通过。
- 原生库重建后已核对：**APK 内 `.so` 与构建产物逐字节一致**。

## 已知边界与未处理项

- **原生超时后的线程/内存回收模型**尚未重做：这属并发与生命周期改动，改错就是
  释放后使用，而本机没有可做功能验证的环境（无 x86 编译器、无 Android 运行时）。
  等有验证条件时再做。
- **星表仍是 Kotlin 源码内嵌**（8419 条）；外置成二进制资源是跨多文件的重构，会影响
  冷启动路径，需独立设计与全量回归。
- **targetSdk 仍是 34**：升级需要本机未安装的 SDK 平台包（当前环境无法下载）。
- **权限申请仍是"进相机页一次性申请相机+定位"**：分级申请要动相机页（含"零每帧分配"
  的硬约束），属设备侧回归项。
- 星表数据的自行修正、GMST 的 UT1/章动项、无障碍与折叠屏适配等精度/体验项未动。

## 安装

- `release` 包与历史版本同一签名证书，可直接**覆盖升级**，无需卸载。
- `debug` 包含调试日志；与 release 签名不同，不能互相覆盖。
