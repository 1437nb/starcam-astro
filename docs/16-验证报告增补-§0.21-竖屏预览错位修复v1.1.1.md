# 验证报告增补 §0.21 — 竖屏预览叠加错位修复 v1.1.1（2026-08-29）

> 可直接粘贴进 `StarRecognizer\docs\验证报告.md`。用户实测 bug 修复。

## 现象与定位

用户实测（v1.1.0，5040 竖拍照片，内置星表引擎解出）：**结果页预览的星座连线
与照片星星错位；同一结果"保存到相册"的图连线正确**。

两处渲染同源（同一 bitmap、同一 WCS、同一坐标），差异在预览路径
（Compose Canvas）的**像素/dp 单位混用**：

1. `dispW/dispH` 由 `onSizeChanged`（像素）算出，却被 `Modifier.size(dispW.dp)`
   当 dp 使用 → 实际渲染尺寸放大 density 倍（~2.75×），照片溢出屏幕、
   仅显示原图左侧一部分；
2. Canvas 内 `a.x * sx`（sx 无 density）在放大后的像素画布上绘制 →
   线条恰好铺满屏幕（线范围 ≈ 屏宽）——**线完整、星星被放大裁切，
   两者必然错位**。保存路径直接用原始像素画 → 正确。

顺带修复：`rescaleSolveFor` 的 crpix 换算应为 FITS 1 起始线性映射
`(p−1)×k+1`，原实现 `p×k` 引入 `(k−1)`px 对角平移（数值验证 2.6px@3.6×；
Python 复刻比对，修后 0.00px）。

## 修复

- `ResultScreen.StarPhotoOverlay`：
  `dispW = with(LocalDensity.current) { (w*scale).toInt().toDp() }`（像素精确转 dp）；
  Canvas 比例改用 `size.width/size.height`（DrawScope 实际尺寸，单位自洽）。
- `StarSolver.rescaleSolveFor`：crpix 改 `(p−1)×k+1`。
- 新增 `RescalePortraitTest`（3 项：横屏/竖屏旋转/竖屏镜像 WCS 的 rescale
  逐星换算误差 <0.05px）；`rescaleSolveFor_math` 断言更新为修正公式。
