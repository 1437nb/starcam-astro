### 1.2 架构与兼容性不变量核验

| 约束维度 | 核验结论 |
| :--- | :--- |
| **手写文件规模上限** | 排除自动生成的星表/字典常量文件后，全仓最大手写文件为 `LocalStarMatcher.kt`（958 行），**0 个手写逻辑/UI 文件超过 1,000 行** |
| **JNI 二进制契约** | `com.starcam.astro.astro.StellarSolverNative` 的 5 个 `@JvmStatic private external fun`（`solve`、`solvePriors`、`extractStars`、`releaseIndexes`、`indexCacheStats`）签名零改动；`libstellar_solver.so` SHA-256 保持 `7848e2118c0519b9ea2eb80317d3e9e24c95bbb05807c97bfd84d99fd74cbd02` |
| **反射调参兼容** | `LocalStarMatcher` 保留全部 `debug*` 与 `lastMatchUsedFallback` 成员字段名，供定标测试台通过 `getDeclaredField` 直接读写 |
| **AR 渲染零分配** | `CameraArOverlay` 的 `Paint`、`NavPaints`、`FloatArray` 投影缓冲与 `SolarFrameCache` 均在 `remember` 一次性创建，绘制闭包内零对象分配 |
| **设置预热与缓存一致性** | `SettingsRepository` 通过 `WeakHashMap<Context, SharedStore>` 按 `applicationContext` 复用同一 `EncryptedSharedPreferences` 与 `apiKeyCache`，使 `StarCamApplication` 后台预热结果直接惠及 `MainActivity`、`StarCamApp` 与 `SettingsScreen` |
