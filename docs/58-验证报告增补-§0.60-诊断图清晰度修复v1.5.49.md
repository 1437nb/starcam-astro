# 验证报告增补：§0.60 失败诊断图清晰度修复 v1.5.49

## 一、问题（开发者 2026-09-12 报）

在结果页打开全屏查看器，于「原图」与「标注图」之间切换并放大后，**标注图明显比原图糊**。
此处的「标注图」指失败诊断图——照片上叠加金色星点圈。

## 二、根因

`ResultScreen.renderDiagnosticBitmap()` 合成诊断图时，把输出固定降采样到**长边 800px**：

```kotlin
val longEdge = maxOf(src.width, src.height)
val viewScale = 800f / longEdge          // ← 固定缩到 800px
val outW = (src.width * viewScale).toInt().coerceAtLeast(1)
```

而原图（`state.bitmap`）由 `ImageUtils.decodeSampledBitmap(path, 2200)` 解码，长边可达 **2200px**。
查看器对两张位图施加同样的捏合放大，高倍率下 800px 的诊断图先触及像素上限，
于是表现为「原图清楚、标注图糊」。

同一文件里的成功页标注图 `renderAnnotatedBitmap()` 用的是与原图**相同**的尺寸
（`Bitmap.createBitmap(src.width, src.height, ...)`），因此不受影响——这解释了为什么
只有失败诊断图有这个现象。

**内存代价**：ARGB_8888 下 2200×1650 约 14.5MB。原先降到 800px 应是为省内存，
但查看器的用途恰恰是放大看细节，这个取舍方向反了。

## 三、修复

`renderDiagnosticBitmap()` 改为输出与原图同分辨率。`DiagStar` 的坐标本就是归一化值
（`x = s.x / diagDisplay.width`，见 `StarSolver.kt`），换尺寸不会错位；
圆半径与描边宽度按「相对原 800px 基准的倍率」等比放大，保持与旧版一致的观感：

```kotlin
val annotationScale = maxOf(outW, outH) / 800f
paint.strokeWidth = 2.5f * annotationScale
canvas.drawCircle(..., (3f + 7f * s.brightness01).coerceAtLeast(3f) * annotationScale, paint)
```

> 若不缩放这两个参数，标注圈在 2200px 图上会比原来小 2.75 倍，几乎看不见。

## 四、验证

| 项 | 方式 | 结果 |
|---|---|---|
| 编译 | `compileDebugKotlin` 在修复后重新执行 | ✅ 通过 |
| 全量单测 | `gradle :app:testDebugUnitTest --rerun-tasks` | ✅ 无新增失败（3 项既有失败为测试素材缺失，与本次改动无关，详见 `docs/57` §5） |
| 真实照片回归 | 指向归档素材复跑 `RealPhotoMatchTest` / `Photo12RegressionTest` | ✅ 通过（识别能力无回归） |
| 真机：查看器清晰度 | 失败页打开查看器，5x 放大来回切换原图 / 标注图 | 待开发者执行 |

> 本修复涉及的 `renderDiagnosticBitmap()` 属 UI 层，JVM 单测不覆盖其渲染结果，
> 故只能验证到「编译通过 + 无回归」，清晰度本身需真机确认。

## 五、遗留

- **真机确认**：失败页打开查看器，放大到 5x 来回切换「原图 / 标注图」，两者清晰度应当一致。
- 若后续为控制内存需要优化，可考虑在查看器关闭时释放诊断图（当前与原图同尺寸，
  两者同时驻留约 29MB）。
