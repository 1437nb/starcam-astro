# 验证报告增补 §0.17 — 识别侧体验修复包 v1.0.3（2026-08-28）

> 可直接粘贴进 `StarRecognizer\docs\验证报告.md`。缺点修复第一批（简单项）。

## 改动（3 处，均基于 §0.15 实测证据）

1. **盲解分段宽场优先**（StarSolver.blindSegments()）
   依据：12 张实拍 + 手机预算模拟，11/12 均由 40°~120° 段命中→ 宽场段（16s）先试、
   窄中场段（3°~40°，12s）兜底。广角/主摄照片（多数用户场景）少等一段。
   限时与总预算不变（28s ≤ 已知视场 30s）。

2. **失败提示加拍摄引导**（ResultScreen）
   识别失败文案追加：「💡 拍摄提示：开启定位并保留照片拍摄时间，GPS + 时间
   能大幅缩小搜索天区、提高识别成功率。」——把"为什么失败、怎么提高"说给用户
   （对应 §5.1-C 建议的落地）。

3. **等待反馈细化**（StarSolver 进度文案）
   盲解轮询文案从「官方引擎求解中（视场 X°–Y°）…」改为
   「官方引擎求解中（视场 X°–Y°，第 i/2 段，约 Z 秒）…」——用户知道还要等多久、
   现在在试哪一段。

## 构建机技能包（本次踩坑，长效备忘）

- **StarCatalogData.kt（919 星对象文件）编译需要大堆**：kotlin IR lowering 阶段
  在 `-Xmx256m` 下必 OOM（表现为"daemon disappeared"或 BackendException）；
  **构建机正确姿势：`GRADLE_OPTS="-Dorg.gradle.jvmargs=-Xmx768m -XX:MaxMetaspaceSize=192m
  -XX:+UseSerialGC -XX:MinHeapFreeRatio=10 -XX:MaxHeapFreeRatio=30"`**。
  768m 编译峰值 RSS ~1.0-1.2GB，需宿主腾内存（本次停用 node-repl MCP 进程
  ~330MB 后成功）。
- `vm.min_free_kbytes` 已从默认 45056 调低到 8192（挤出保留页，缓解 OOM）；
  重启后需重设：`echo 8192 > /proc/sys/vm/min_free_kbytes`。
- 无效选项警告：AGP 8.x 已移除 `android.enableAapt2DaemonMode`（勿再加回）。
- `org.gradle.workers.max=1` 已固化在 gradle.properties。
