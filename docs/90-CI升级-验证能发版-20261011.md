# 90 · CI 升级：从「跑单测」到「真的验证能发版」（2026-10-11）

> 来源：外部审计报告（2026-10-06）P1 第 2.1 条 +《待修清单》§三-1
> 相关：`docs/88`（验证机与全量单测验收）、`docs/89`（§0.104 native 重编时人肉发现的
> 16 KB 对齐坑 —— 本升级正是要把这类问题交给 CI 拦）

---

## 1. 为什么做

审计的原文理由：**「项目已经踩过『debug 能过、release 被 R8 打爆』的坑（v1.5.56/57
Tink 注解类），即已发生事故却还没装护栏」**。

2026-10-11 又出现第二个同类：重编 `libstellar_solver.so` 时，服务器脚本缺
`-z,max-page-size=16384`，产物是 4 KB 对齐 —— 直接替换会破坏 Play 的 16 KB 页要求。
**两次都是"人肉发现"，两次都不该靠人记得。** 本次把这两类检查固化成 CI 硬门禁。

## 2. 新增的三个 job（`.github/workflows/ci.yml`）

| job | 做什么 | 拦什么 |
|---|---|---|
| `android-build` | `assembleDebug` + `assembleRelease`（CI 无签名密钥 → release 为未签名包），产物上传为 artifact | 「debug 过、release 炸」：R8/资源合并/lintVital 的整条发版链路 |
| `android-lint` | `:app:lintDebug`，报告上传 | 新增的 lint error（现有问题见 §4 已清） |
| `binary-audit` | 对两个 APK 做二进制审计（见下） | 16 KB 页要求、.so 缺失/被压缩、调试入口进公开包、签名形态漂移 |

`binary-audit` 的六条判据，每条都对应一次真实事故或平台硬要求：

1. `lib/arm64-v8a/libstellar_solver.so` **必须在**（缺了等于没有求解引擎）；
2. `.so` 的 `PT_LOAD` **必须 16 KB 对齐**（`readelf`，全部 `0x4000`）；
3. `.so` 的 **JNI 入口符号必须在**（防"能链接但没入口"的库）；
4. `.so` 在 APK 内**必须未压缩**，且**数据偏移对 16384 整除**
   —— 与 2026-10 审计的验收口径一致。**不用 `zipalign -P 16`**：该旗标在
   build-tools 34 上不存在（是 35+ 的），各 runner 版本不一；直查字节更可靠；
5. `release` 包**不得含 `AutoTestActivity`**（调试入口不得进公开包）；
6. `debug` 已签名 / `release` 未签名（CI 无密钥）—— 与预期不符即失败（流程变更时
   这个检查会提醒同步更新）。

## 4. lint 接入过程中清掉的 24 个 error（附一个真 bug）

接入时 `lintDebug` 报 **24 errors / 19 warnings**，全部清掉：

**19 个 `UnsafeOptInUsageError`（CameraScreen.kt）—— 这是真的写错了，不是误报**：
文件里原有的 `@OptIn(androidx.camera.camera2.interop.ExperimentalCamera2Interop::class)`
用的是 **Kotlin 内建的 `@OptIn`**，而它只认 `kotlin.RequiresOptIn` 标记，
**对 androidx 的 Java 标记无效**（所以一直没生效）。改为 lint 要求的
**`androidx.annotation.OptIn`** 后清零。纯注解、无运行时行为变化。

**5 个 `ProduceStateDoesNotAssignValue`（History/History/Gallery/Gallery/Demo）——
判定为规则误报，定点豁免**。判据：
- 代码里 `value = …` 确实在 producer lambda 顶层（逐处读过，无同名遮蔽）；
- 这些界面在真机上一直正常显示（照片缩略图/相册/统计都出来了）—— 赋值显然生效；
- 疑似与 Kotlin 2.0（K2）UAST 下的规则识别有关。
处理：在这 5 个函数上加 `@Suppress("ProduceStateDoesNotAssignValue")` 并写明理由，
**保留规则对新增代码的约束**（新增的 produceState 写错仍会被拦）。

## 5. 未覆盖 / 风险

- CI 里的 `assembleRelease` 只验证**能构建、R8 不炸、产物形态正确**；签名与真机安装
  仍由维护者用 `tools/release.py` 在带密钥的机器上完成；
- `android-build` 与 `android-lint` 各占一个 runner：CI 总时长明显增加（单测 4~5 分钟，
  构建 ~10 分钟，lint ~10 分钟，可并行）；
- 二进制审计只覆盖 arm64-v8a 的 `.so`（当前唯一 ABI；将来加 ABI 需同步扩展）。
