## 2. 跑全量单测（含 8 个真值回归类）

```bash
cd ~/starword/code
GRADLE_OPTS='-Dorg.gradle.jvmargs=-Xmx1024m -XX:MaxMetaspaceSize=512m' \
  ./gradlew --no-daemon --console=plain --max-workers=1 --no-configuration-cache \
  -Pkotlin.compiler.execution.strategy=in-process :app:testDebugUnitTest --rerun-tasks
```

要点（踩过的坑）：

- 仓库 `gradle.properties` 是按 8GB 开发机调参的（`-Xmx2g`、Kotlin 守护 `-Xmx2g`、
  `workers.max=4`），在 3.8GB 机器上**必须用 `GRADLE_OPTS` 覆盖**（上面的命令即
  覆盖版，与 CI/本机的标准命令等价于同一批测试）；
- `--max-workers=1` 会把测试 fork 限制为 **1 个**（`maxParallelForks=2` 不生效）：
  内存最稳，代价是全量测试串行、约 40 分钟；内存有余量时**去掉它**可恢复并行提速；
- `testdata/` 放在 `<repo>/testdata` 即可 —— 测试按**相对路径**自动探测
  （2026-10-08 的路径收敛改动），无需再设 `PHOTO_DIR` / `PHOTO12_DIR` / `NF_DIR`；
- Kotlin 编译在 2 核机器上约 15 分钟、峰值内存 ~2.6GB（测试阶段），3.8GB 全程无 OOM。

## 5. 重建/维护（约 10 分钟，全自动）

1. 装工具链：`sudo dnf install -y git java-17-amazon-corretto-devel`；
2. 装 Android SDK：下载 `commandlinetools-linux-*_latest.zip` → `sdkmanager`
   安装 `platforms;android-34` `build-tools;34.0.0` `platform-tools`（先 `--licenses`）；
3. 克隆仓库并写 `code/local.properties`（`sdk.dir=<该机 SDK 路径>`）；
4. 传素材（从构建服务器，实测 ≈18MB/s、约 35 秒）：
   ```bash
   tar cf - testdata/{gray12,narrowfield,realphotos,photos12,photos12-wcs,nf_test1.fits} \
     | ssh <别名> 'mkdir -p ~/starword/testdata && \
         tar xf - -C ~/starword/testdata --strip-components=1'
   ```

> 注意：实例是**一次性**的（重建后以上步骤需重跑）；`~/starword` 不承载任何
> 未入库的产出（测试结果、日志都留在该机，不进仓库）。
