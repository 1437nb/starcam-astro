# StarCam v1.5.61 更新说明

**主题：修复 SEP 提星阈值语义误用（§0.72）**

## 修复内容

### 1. 修复「原图识别不出来、高对比度版却能识别」（核心问题）

用户 2026-09-17 拍摄的原图此前识别失败，但把对比度拉高后就能识别。
根因在**提星环节**——App 引擎在照片里"看到的星"其实全是噪声。

**技术说明**：提星器的阈值参数被误用。调用方传的「背景噪声倍数」被直接当成
提星器的「峰值显著度」使用，而两者的换算差了一个约 3.5 倍的系数：

- 传入 2.0（本意是「2 倍噪声」）→ 实际只相当于 **0.56 倍噪声**，**低于噪声本身**；
- 结果整幅图 **29% 的像素**都超过检出限，被连成一个 **85 万像素**的巨块，
  超过提星器的"延展天体"上限（2000 像素）后被**整体丢弃**；
- 真星全部丢失，只剩图像边缘（背景估计失效区）的零碎噪声团块 ——
  用户日志里那 172 颗"星"就是这么来的。

**证据**：这 172 颗星里，**0 颗**落在真实亮源上（真星处像素为 255 饱和，
而这些位置最高只有 94）；**73%** 落在距图幅边缘 30 像素内（该区域面积仅占
6.3%，富集 11.6 倍）；最大亮度 96.7，而同一张照片的真实星是 4143。

**修复后**：过阈像素从 29.27% 降到 0.63%，最大连通域从 848,846 像素回到
55 像素（正常星点大小），真星得以正常检出。

### 2. 新增提星诊断日志（应要求）

识别日志现在会记录**提星过程**：检出星数、边界剔除数、亮度范围、
边缘占比、以及与内置检测器的重合率。这样下次若仍有失败，
日志能直接指出是"提星没提到星"还是"提到了但匹配不上"。

### 3. 附带的健壮性改进

- **边界过滤**：剔除距图幅 16 像素内的检出点（提星器的背景估计在边缘失效，
  会产生伪影）。对正常照片仅损失 2.5~2.9% 的星点。
- **提星质量核验**：若提星结果与内置检测器的亮星重合率过低（<30%），
  判定本轮提星不可信，自动改用内置检测器结果，避免"提星退化导致整个引擎白跑"。
- **阈值下限保护**：换算结果低于 4.0 时钳制到 4.0，防止再次跌入噪声区。
