# 验证报告增补 §0.27 — 跨引擎星点复用 v1.5.0（2026-08-30）

> 可直接粘贴进 `StarRecognizer\docs\验证报告.md`。

## 背景（第三/四/五轮真机数据的收敛）

- 独立 arm64 诊断可执行文件（与 .so 同工具链、同 simplexy 调用）在真机
  CPU 上对 4984 提出 **462 颗星、rc=1（正常语义）**——simplexy 算法与
  arm64 编译均无问题。
- 但 APP 内 .so 的 detect_stars 依然 0 颗（rc=0, nstars=0）→ 问题定位为
  **.so 内部调用上下文**（APP 进程内的某种状态/交互），继续深挖成本高。

## 修复：跨引擎星点复用（绕开方案）

自研引擎的 SEP 提星在真机上**工作正常**（5 张解出即证明）。v1.5.0 让
官方引擎直接复用 SEP 的星点：

1. `StellarSolverNative.solveBitmapImpl`：先 `sepDetectStars(bitmap, 2.0, 300)`
   （≥4 颗时）打包为 `[n, x0,y0,f0, x1,y1,f1, ...]` float 数组；
2. JNI `solve/solvePriors` 新增 `extStars: FloatArray?` 参数；
3. C `run_solver`：外部星点 ≥4 颗时直接构建 `starxy_t`（跳过 detect_stars），
   否则回退 simplexy（行为兼容）；外部星点的坐标/量纲约定与 simplexy 输出
   一致（0 起、y 向下、亮度累计），quad 构建的亮度排序语义保留。
4. 同时修复真机判读中发现的字段笔误（brightness）。
