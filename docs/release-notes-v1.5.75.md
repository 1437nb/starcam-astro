# StarCam v1.5.75 更新说明

**主题：稳定性与可验证性加固 —— 五条 P0 修复 + CI 硬门禁**

这一版没有新功能，做的是「把已经发生过的坑变成不可能再发生」：并发安全、
批量识别计数、识别日志归属、深域兜底收口、native 超时接盘，共五条 P0；
外加把 CI 从「跑单测」升级为「真的验证能发版」。

## 修复（用户可见）

### 1. 批量识别不再有并发隐患（§0.100 / §0.101）

- 两处共用的 `SimpleDateFormat` 换成线程安全的 `DateTimeFormatter` ——
  批量识别两个 worker 并发跑时，文件名时间戳与 EXIF 时间解析不再可能互相踩踏；
- 批量完成时的统计改为**强类型结果**逐项记账，「已识别 / 已保存 / 失败」
  三个计数与每张照片的实际结局严格一致，不再可能出现"解出却计成失败"。

### 2. 识别日志可按次归属（§0.102）

- 每行日志带上 `solveId` 与照片名（`[S042][photo5031.jpg]`）——
  批量两个 worker 的日志混在一起时，也能按行分清是谁的；
- 失败现场目录名带 `solveId`，不再出现同秒两次失败互相覆盖现场的问题。

### 3. 深域兜底收口（§0.103）

- 视场大于 45° 的广角照片**不再进入深域重试**：那条路数学上不可达，
  真机实测只会白跑 60 秒、产出尺度坍缩的伪解；
- 手机自带 EXIF 视场（可信来源）现在会传给匹配器做提示，深域是窄场兜底、
  宽场在浅域就该解出 —— 这条判定只用 EXIF 视场，绝不用失败候选反推的视场。

### 4. native 引擎超时不再泄漏（§0.104）

- 官方引擎单次求解超时后，原先 worker 线程与 11MB 索引会永久滞留
  （"超时一次、余生不可回收"）；现在用原子所有权状态机接盘：
  超时后线程自然收尾并归还资源，索引缓存可正常回收，进程长期运行不再累积。

## 工程与质量（这一版起 CI 替你把关）

- **CI 升级为「真的验证能发版」**（docs/90）：除单测与凭据扫描外，新增
  `android-build`（debug+release 全链路装配）、`android-lint`（0 error，
  顺带修掉 19 个真实存在的注解错误）、`binary-audit`（.so 必须在 / 16 KB 页对齐 /
  未压缩 / JNI 入口在 / release 无调试入口 / 签名形态符合预期，六条判据）；
- **CI 新增真实照片真值回归**（docs/91）：用 app 自带的 12 张公开演示照，
  在 CI 里现场解码、走生产「选表 → 匹配」路径，硬线是 **12/12 真解、假阳性为零**；
- 全量单测 215 → **229 项 / 33 类**，验证机全绿；CI 五 job 全绿。
