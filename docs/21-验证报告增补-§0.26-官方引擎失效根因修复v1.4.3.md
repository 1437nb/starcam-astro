# 验证报告增补 §0.26 — 官方引擎手机端失效根因修复 v1.4.3（2026-08-30）

> 可直接粘贴进 `StarRecognizer\docs\验证报告.md`。**项目最重要的一次修复**。

## 根因（四轮真机数据 + x86 复现逐层锁定）

四轮真机数据（v1.3.5→v1.4.2）排除了预算、并行、输入灰度后，x86 复现诊断程序
触发断言并溯源源码，找到**双重根因**：

1. **`simplexy_run` 的返回值恒为 1**（simplexy.c 第 499 行硬编码 `return 1`，
   非错误码，历史遗留语义）。x86 诊断实测：对 4984（真机失败照片之一）
   提出 **669 颗星**时 rc 仍为 1。
2. 而 APP 的 `detect_stars` 失败条件写了 `rc != 0 || npeaks < 4` ——
   **669 颗星被 rc=1 一票否决**，JSON 报 `nstars=0`。

**后果**：官方引擎（astrometry.net 主引擎）在手机上**从 APP 第一版起
从未成功提过星**——`solveBitmap` 官方路径 100% 秒败。文档 §4.2 的
"官方盲解 6/12"全部来自服务器 x86（solve-field 走 engine 管线、不检查
此返回值），掩盖了这个 bug。同 .so 的 SEP 提星入口（自研用）恰好是
正确调用顺序（defaults 先、赋值后），因此自研引擎一直正常。

顺带定位：`simplexy_set_defaults` 首行 `memset(s,0,sizeof)` 会清掉
先赋值的 image/nx/ny（x86 诊断以断言形式复现）——detect_stars 的
赋值顺序需在 defaults 之后（本次一并核对，SEP 路径本就正确）。

## 修复（v1.4.3）

- `detect_stars`：成败只看 `npeaks >= 4`，rc 仅记录不否决（源码注释
  说明 return 1 语义）；失败诊断保留 rc/峰值数/灰度统计。
- `.so` 重新交叉编译，JNI 符号验证。
