## 1.1 识别链路总览（三层混合引擎 + 并发竞速）

```
拍照 / 统一文件导入（普通图片 / RAW / FITS）
   │  先验提取（SolverPlanning.readFovDeg + ExifPriors.kt + FitsImage.kt）
   │    ├─ 35mm 等效焦距 / FITS WCS 头 → 可信 FOV 区间（FovEstimate.kt）
   │    └─ EXIF GPS/时间 或 当前定位/传感器指向 → 天区先验 RA/Dec（SkyEphemeris.kt）
   ▼
StarSolver.solve(context, bitmap, imagePath, settings, token)  ← 调度与预算守门
   │  策略规划：SolverPlanning.planSteps / canRace（双引擎并发竞速 §0.114）
   │
   ├─[步骤① LocalMatcherStep → LocalStarMatcher（内置 8,419 星分级星表，≥8° 宽/中场）]
   │    ├─ StarFieldDetector：灰度转换、滑窗均值减背景、连通域峰值质心、亮源掩模
   │    ├─ TriangleStarIndex：浅域（≤4.0 等）/ 中域 / 深域（≤6.5 等）三角形比值索引与天球网格
   │    ├─ TriangleVoteScorer：多线程并行三角形投票 + 宽场一对一假设打分（scoredRound）
   │    ├─ StarFieldFitter：TAN 切平面相似变换拟合、RANSAC 内点过滤与全星表精化 → WcsTransform
   │    └─ 复杂背景/前景补救：ComplexFieldExtractor + SkyRegionRecovery + SkyRegionCalibration
   │
   ├─[步骤② NativeSolveStep → StellarSolverNative（astrometry.net 0.97 NDK .so，0.1°~180°）]
   │    ├─ NativeSolverSupport：8 档 4100 系列 FITS 索引原子解压自愈 + WCS JSON 解析
   │    ├─ 有天区先验 → solvePriors(ra, dec, radius)（solver_set_radec 通道）
   │    └─ 无先验 → blindSegments 宽场优先分段盲解 + 降采样重试 + SolveToken 轮询中断
   │
   └─[步骤③ OnlineNovaStep → PlateSolveClient（nova.astrometry.net 在线 API 兜底，独立 ≥150s 预算）]
        └─ login → upload（downsample_factor=2 + degwidth 视场范围）→ 退避轮询 → calibration WCS（y-down 对齐）解析
   ▼
ResultViewModel（IO 线程预计算投影）→ ResultScreen 渲染与导出
   ├─ LayeredRenderer + StarChartOverlay + BoundingBox（4 象限防碰撞标注 + 近邻星名抑制）
   └─ PhotoExportActions + PhotoExporter（预览尺寸 / 原图尺寸标注导出、纯净星座连线图）
```

## 1.3 JNI 桥与坐标系核心约定

1. **JNI 导出符号（`code/app/src/main/cpp/astro_bridge.c`）**：
   - `Java_com_starcam_astro_astro_StellarSolverNative_{solve, solvePriors, extractStars, releaseIndexes, indexCacheStats}`（外加桥接源码指纹符号），编译产物 `libstellar_solver.so` 满足 **16 KB 页对齐**。
2. **J2000 统一历元**：
   - 内置星表、4100 系列 FITS 索引与 `WcsTransform` 一律采用 **J2000**；新增太阳系或瞬变天体必须归算至 J2000 后再投影，否则产生岁差整体偏移。
3. **像素坐标系方向**：
   - 屏幕与 `Bitmap` 像素满足 $x$ 向右、$y$ 向下；FITS 标准像素满足 $y$ 向上，`WcsTransform` 已在内部完成双向符号对齐，外部调用统一传图像像素坐标。
