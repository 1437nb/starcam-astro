## 2. 机制

同一份**干净**星表（32 颗）本机解出 `16/30 = 0.533`；真机那份 177 颗却只有 `8/206`。
差异只能来自多出来的 ~145 颗：它们把**邻域表（每锚点取最近 14 颗）与候选生成挤坏**
—— 真解候选根本生成不出来（不是门槛误杀，注意 `best` 只有 8）。

本机复现（`FallbackStarListTest`，固定种子）：在 5031 的干净星表里注入 100 颗**与真星同量级**
（150~500）的噪声星 → 主列表解不出；而干净列表仍可解出。若噪声**暗于真星**则完全无害
（打分轮工作集取最亮 45 颗，暗噪声进不去）——这与真机「最亮的 8 颗仍是真星」的读数吻合。

## 3. 修复

`LocalStarMatcher.match` 新增可选参数 `fallbackDetected`（第二个检测器的星表）：

```kotlin
match(detected, width, height, hint, allowDeepRetry, fallbackDetected)
```

浅域阶梯在主星表上失败后：

1. 先把**主星表浅域**那一轮的数字留档（§0.86 的失败页要能分轮显示）；
2. 用备用星表在**浅域**再试一次；成功即返回并置 `lastMatchUsedFallback`；
3. 两者都无解才进深域重试（顺序：备用列表**先于**深域——宽场下深域不可达，
   先白等 60 秒没有意义；备用列表通常更稀疏，这一步便宜）。

`StarSolver` 把已经算好的 box-blur 列表作为 `fallbackDetected` 传入（它在 §0.72 的
「SEP 可信度核验」里本来就要算），命中时写一行识别日志。

### 3.1 为什么不是「让 SEP 星表更干净」

- SEP 阈值收紧会连带损失暗星检出（§0.72 的教训：本机无法运行 native SEP，调参只能盲调）；
- 交叉核验只回答「SEP 是否漏掉了 box-blur 看到的亮星」，无法识别「SEP 多出来的星有没有害」；
- 备用重试直接以**结果**为准：一个列表解不出来就换另一个，两个检测器互为独立证据。

## 5. 遗留

- **真机仍未复测**：预期真机浅域会先用 SEP 列表跑到上限（约 25 秒，这是 §0.87 上限的代价），
  失败后由 box-blur 备用星表在浅域接管并解出。
- **失败路径耗时**：主星表被污染时，25 秒是「跑到候选上限」的成本。若真机实测等待过长，
  可考虑的方向：按列表规模自适应上限、或对明显膨胀的列表先做一次便宜的质量判定
  （例如与 box-blur 的数量比），而不是等它跑满。
- box-blur 备用列表在真机上未被独立观测（本机用 bilinear 像素复刻为 28 颗、可解）。
