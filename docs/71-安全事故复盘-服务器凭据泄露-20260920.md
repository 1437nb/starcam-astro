# 安全事故复盘：服务器凭据泄露（2026-09-20 发现）

> **结论先行**：`tools/gh_socks_tunnel.py` 里硬编码了构建服务器的 root 口令与 IP，
> 随提交进入**公开仓库**并暴露约 2 天。**必须立即轮换该服务器口令**——
> 即使仓库已清理，旧 git 对象在 GitHub 完成 GC 前仍可按 SHA 直接读取。

## 二、根因

### 2.1 直接原因：凭据硬编码

脚本为了「一条命令跑起来」把 SSH 口令写成了模块级常量。它起源于更早的会话，
但**在本次多次推送中持续被发布**，而推送前从未审查 `tools/` 目录内容。

### 2.2 为什么 CI 的凭据扫描没拦住（关键）

CI 里配了 `gitleaks/gitleaks-action@v2`，但它走的是**默认规则集**，
默认规则只匹配**已知凭据格式**：

- AWS Access Key（`AKIA…`）
- GitHub Token（`ghp_…` / `github_pat_…`）
- Slack / Stripe / Twilio 等服务的固定前缀
- 私钥块（`-----BEGIN … PRIVATE KEY-----`）

而本次泄露的形态是「**自定义变量名 = 任意字符串口令**」——
上游为控制误报率**刻意不覆盖**这类通用赋值。所以扫描"通过"是必然的，
**不是配置错误，而是规则覆盖盲区**。

### 2.3 流程原因

- 本机 `git push` 被墙，推送走自研的 `gh_api_push.py`（GitHub Git Data API）。
  这条路径**绕过了任何本地钩子**（pre-commit / pre-push），且脚本本身不做凭据检查。
- 发布流程里没有「发布前审阅 diff」的固定动作。

## 四、待办（**需要开发者操作**）

### 4.1 立即：轮换服务器口令（最高优先级）

**这一步只能由你完成，且必须做。** 原因：

- GitHub 对已"不可达"的 git 对象**并不会立即删除**。实测：远端 ref 全部更新后，
  按旧 SHA 仍能读到含口令的文件内容（本次验证确认），要等 GitHub 后台 GC。
- 在 GC 完成前，任何拿到旧 SHA 的人（或已被爬取的副本）仍可读到口令。
- 口令已暴露 2 天，应视为**已泄露**。

操作建议：

```bash
ssh root@<服务器>
passwd                      # 改口令
# 顺带检查是否有异常登录/密钥：
last -20 ; cat ~/.ssh/authorized_keys ; grep -i "Failed password" /var/log/secure | tail
```

改完后更新本机 `~/.starcam/ssh-tunnel.env` 的 `PASS=`。
（注：本次排查时该口令已认证失败，可能你已改过；如已改请忽略。）

### 4.2 建议：为脚本改用 SSH 密钥 + 非 root 账户

口令轮换只解决这一次。长期建议：

- 生成专用密钥对，`~/.ssh/authorized_keys` 授权给**非 root** 的转发专用账户
- 该账户仅需 `AllowTcpForwarding yes`，用 `Match User` 限制来源 IP
- 彻底消灭「口令写在某处」的可能性

### 4.3 建议：给推送脚本加发布前检查

`tools/gh_api_push.py` 是绕过本地 git 钩子的唯一推送通道，建议在 `cmd_push()`
开头插入：

```python
subprocess.run([sys.executable, os.path.join(WD, "tools", "check_secrets.py")], check=True)
```

## 五、教训

1. **公开仓库里没有"临时"凭据。** 任何写进源码的凭据都要按"已公开"对待。
2. **默认规则的扫描器给不了默认的安全。** gitleaks 默认集只认固定格式；
   自有项目必须按自己的形态补规则 —— 本次漏检的正是最常见的
   "变量名 + 字符串口令"。
3. **"扫描通过"要能解释通过的原因。** 当时看到 secret-scan 一路 success
   就认为安全，但没人确认过它到底覆盖什么。绿灯不等于覆盖。
4. **绕过标准通道的推送路径要自带守门。** 自研 API 推送绕开了所有 git 钩子，
   这类脚本必须自己先跑一遍凭据检查。
5. **发布前审阅 diff 是最后一道闸。** `tools/` 这种辅助目录最容易藏东西，
   恰恰最容易被"我只改了 app 代码"的惯性忽略。
