## 一、识别历史/收藏（纯 Kotlin）

- **存储**（新增 `data/HistoryStore.kt`）：SharedPreferences + JSON，免新依赖；
  上限 50 条（新的在前）；单条损坏自动跳过。
  字段：时间/图片路径/中心 RA/Dec/视场/引擎详情/最近星座中文名
  （`nearestConstellationZh`：遍历 919 星表取天区中心最近星的星座）。
- **写入**（ResultScreen）：识别成功后自动记录（demo 模式不记）；缓存目录被系统
  清理后条目保留，重新打开时按"无法读取照片文件"提示。
- **页面**（新增 `ui/history/HistoryScreen.kt`）：按时间倒序列表（星座+日期加粗、
  坐标/视场/引擎详情），点击条目重新打开对应照片识别；顶部"清空"按钮。
- **导航**：`Screen.History` 路由 + 主页「🕘 识别历史」入口。

## 二、.so 诊断增强（astro_bridge.c 重编译）

1. **修复索引内存泄漏**：查证 `solver_free`→`solver_cleanup` 仅 `pl_free(indexes)`
   （只释放列表结构，不释放 `index_t*`，所有权在调用方；`pl_free_elements` 才释放
   元素）——**旧版每次求解 index_load 8 档（~11MB）且从不释放 = 每次泄漏**。
   新版按路径进程级缓存 `index_t*`（`g_index_cache` + mutex），首载后零加载成本
   ——同时消除 §0.15 差距诊断第 2 条（索引加载吃盲解墙钟预算）。
2. **提星数诊断**：JSON 输出新增 `nstars`（成功/失败各路径均带）——真机失败时
   可直接看到 simplexy 提了多少星，定位"提星质量"嫌疑（§0.15 差距诊断第 1 条）。
3. **提星参数可调**：JNI `solve/solvePriors` 新增 `plimOverride` 参数
   （0=引擎默认 8.0；调低→检出更多弱星），Kotlin 侧默认 0（行为不变），
   真机诊断后可针对性启用。`SolveResult` 新增 `nStars` 字段。
4. **重编译**：NDK r26d（路径 `/opt/ndk/android-ndk-r26d/`，与文档 §3.7 的
   `/opt/ndk` 略有出入）arm64 编译 astro_bridge.c + 链接源码树既有 .a 交叉产物；
   `llvm-nm` 验证 JNI 导出与 `simplexy_set_nthreads`/`an_smooth_parallel` 符号完整；
   新 .so 5,093,040 B（旧 5,092,496 B），旧版已备份 `/tmp/libstellar_solver.so.bak`。
