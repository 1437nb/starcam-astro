# 验证报告增补：§0.49c AR 射线扇面修复 v1.5.37

## 一、现象（真机截图反馈）
AR 实时星图使用中，画面边缘外一个点向外发散出大量直线（射线扇面），
横穿整个取景画面，严重遮挡视野。两张截图（方位 346°/262°）中扇面
汇聚点均位于画面左下角边缘外。

## 二、根因：帧间复用数组被"清零"而非"清 -1"（v1.5.35 引入）

AR 星图的星座连线按"星表下标对"绘制：每帧先把本帧可见星登记到
`visibleIdx`（目录下标 → 屏幕星列表槽位），再遍历星表线段，
**两端下标都登记过才画线**。

为避免每帧分配 8419 长度的数组，`visibleIdx` 被设计为跨帧复用，
复用前用 `System.arraycopy(emptyVisIdx, …)` 重置——但 `emptyVisIdx =
IntArray(n)` 的默认值是 **全 0 而不是全 -1**，而 `0` 是合法槽位号
（第 0 颗可见星）！

后果：任何"一端在本帧视野外"的星座线段（仰角 52°~55° 朝天花板时，
大量星座被地平线/视场边缘截断，此类线段极多），其不可见端点被解析为
槽位 0 → 全部被错误地画成"可见星 → out.stars[0]"的连线。out.stars[0]
是本帧第一颗可见星（恰好在画面边缘附近，且在裁剪矩形外被裁剪），
于是几十条假线从同一个点发散——**射线扇面**。

## 三、修复
1. `ArSkyProjector`：复用重置改为 `java.util.Arrays.fill(visibleIdx, -1)`，
   删除错误的 `emptyVisIdx`。
2. **回归测试加固**（`messierAndLinesProjected`）：新增"每条绘制连线的端点对
   必须是星表真实线段"断言——原测试只验证端点在可见星集合内，
   无法发现"错误连到 stars[0]"的假线；新断言可精确拦截此类 bug。

## 四、验证
- `testDebugUnitTest` 全量回归通过；
- `assembleDebug` 构建成功：`StarCam-v1.5.37-AR射线扇面修复-debug.apk`（仅 debug）。
- 真机复测：同样朝向（西北天空/天花板）下不应再出现从单点发散的射线；
  星座连线只应出现在星表定义的星对之间。
