4. **识别阶段与计时**：提供准备、检测、本地匹配、原生求解、并行、复核、在线、渲染等稳定阶段事件；显示已用时间和配置的总预算，不伪造完成百分比。

## 二、资源开销治理

### 2.1 单次求解图像输入

`SolvePixels` 以同步 lazy 保证并发引擎只从 Bitmap 转换一次共享灰度。box-blur 检测和失败诊断复用它，减少重复 `getPixels` 与同尺寸 IntArray / FloatArray 分配。

JNI/simplexy 仍接收自己的数组副本，避免在没有上游源码保证的情况下让原生代码修改共享检测输入。原生步骤内部继续复用该私有输入处理多轮先验与盲解。匹配器的提星数量上限、亮度权重、星表与判据没有调整。

### 2.2 统一绘制器

`RenderPaints` 扩展为每个调用方持有的绘制上下文：

- 线段缓冲、字体指标复用；
- 占位边界盒按最高用量复用，不在每个标签处构建新对象；
- 星名候选列表与排序存储复用，排序保留同星等的原有次序；
- 四象限位置计算改为标量循环和输出缓冲，移除 Pair / List / LabelPlacement 的逐标签创建；
- 名称按语言缓存；角度比例尺用 primitive Float，缺失以 NaN 表达，避免 AR 调用装箱。

原有纯函数包装保留，便于 JVM 标签位置回归；AR、结果预览、放大查看和位图导出仍使用同一套碰撞与边界规则。

这不是“真机帧率已提升 X%”的声明。池子与名称在首次遇到更高可见数量时允许扩容；当前验证覆盖稳定场景的布局热路径复用，设备端帧时间与耗电需另测。

## 三、随版本补齐的上传保护

- 上传缓存改为原子创建的唯一临时文件，避免毫秒文件名撞车。
- 上传去重流式哈希整个文件，避免同头同长度的不同照片误判。
- 用 URL 解析后的 scheme / host 校验 HTTPS 与精确回环例外，拒绝伪回环域名和 URL 用户信息段。

复核时发现 `network_security_config.xml` 本来就有独立平台保护，原 docs/111 D04 把函数校验绕过等同于实际公网明文泄露的风险判断过重，已在原报告明确更正。本次应用层例外只放行 localhost / 127.0.0.1，与现有 Android 配置一致。
