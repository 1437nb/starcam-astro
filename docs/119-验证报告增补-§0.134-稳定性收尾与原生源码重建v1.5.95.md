## 从固定源码恢复 native 构建

原文档中的 `C:\dev\astrometry-local` 和独立 NDK 目录缺失，维护者确认没有备份。本轮已用本机 Windows NDK + CMake 从固定源码重建，不依赖旧 `.a` 包或 Linux 构建机。

- 上游：[astrometry.net 0.97](https://github.com/dstndstn/astrometry.net/releases/tag/0.97)、[CFITSIO 3.47 源码归档](https://ftp.eso.org/pub/dfs/pipelines/libraries/cfitsio/)。下载 URL 和 SHA-256 固定在 `tools/build_native.py`。
- 工具链：Python 3.12+、SDK `ndk;26.3.11579264`、`cmake;3.22.1`，Android API 26。
- 脚本按上游 Makefile 对象清单生成本机 CMake 工程，逐次使用新构建目录；源码缓存、日志和静态库均留在忽略的 `code/app/build/`。
- 明确补丁：`quit_now` 改为 C11 原子标志；修复旧 CFITSIO 的动态格式字符串；不编译 JNI 未引用且源码归档缺少生成数据的 OpenNGC 命令行模块。
- 成功链接、架构 / 6 个 JNI 导出 / 16 KiB ELF LOAD 对齐 / 内嵌桥接源码 SHA-256 校验通过后，才复制最终 `.so` 并生成 sidecar。构建失败不会冒写成功指纹。
- 生产库仍仅 `arm64-v8a`。`x86_64` 仅通过显式 `-PnativeEmulatorTests=true` 进入 Debug，便于实际执行新 JNI；默认 Debug 与 Release 不包含该测试库。
- [最终两种 ABI 构建指纹与 C 桥检查](compatibility/20261103-v1.5.95-native-build.json)。产物已去除调试符号，大小变化不作为正确性证据。

```powershell

tools\build_so.bat
python tools/build_native.py --fetch --abi x86_64 --output code/app/build/native-emulator/x86_64/libstellar_solver.so

cd C:\starcam\code
.\gradlew.bat :app:assembleDebug -PnativeEmulatorTests=true --offline --console=plain
.\gradlew.bat :app:assembleDebugAndroidTest -PnativeEmulatorTests=true --offline --console=plain
cd C:\starcam
python tools/android_acceptance.py --serial emulator-5554 --install --ui
```

无测试 native 的默认回退验收：分别重新执行两个 Gradle 命令时去掉 `-PnativeEmulatorTests=true`，再执行验收脚本。测试与打包始终使用分开的串行 Gradle 命令。
