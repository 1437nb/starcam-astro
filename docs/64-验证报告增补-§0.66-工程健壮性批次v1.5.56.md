# §0.66 工程健壮性批次（v1.5.56）

> 修复日期：2026-09-17
> 上一版 §0.65 修掉了「识别不出来」的根子；这一版处理的是「不做就一直漏」的
> 工程债：凭据保护、构建可移植性、回归自动化、相机链路浪费、在线客户端加固。

## 1. 凭据保护：API Key 改加密存储

`SettingsRepository.apiKey` 原先存在普通 `SharedPreferences`（`MODE_PRIVATE`）。
该模式只挡其他应用，挡不住 root / 取证工具的直接读取，而 API Key 是可计费凭据。

改为 `EncryptedSharedPreferences`（AES256-GCM，主密钥在 Android Keystore）：

```
starcam_secure_settings（加密）
  └ api_key
starcam_settings（普通，仅存非敏感项）
```

**迁移与回退**：读 key 时若加密项为空而普通项有值，自动搬进加密项并删除明文项
（老用户无感升级）。加密存储初始化失败（极少数 ROM 的 Keystore 异常）时降级为
普通存储——宁可降级也不能让用户配不了 key，降级会打 `Log.w`。

## 2. 构建脚本去硬编码

`keystorePropsFile` 原为绝对路径 `C:/dev/starcam-keystore.properties`，导致
任何其他机器（含 CI）都读不到签名配置、只能产出未签名 APK。现按顺序查找：

```
STARCAM_KEYSTORE 环境变量（CI 用 secret 注入）
  → -PkeystoreProps=<路径>（本机命令行）
  → ~/.starcam/starcam-keystore.properties（本机默认位置）
```

三者都没有则降级为未签名 APK（原行为），且公开仓库不再暴露开发者目录结构。

## 3. 回归自动化（CI）

新增 `.github/workflows/ci.yml`：任何 push / PR 自动跑纯 JVM 单测 + gitleaks
凭据扫描。单测不依赖 native，GitHub 托管的 x86 runner 就能跑，不需要 arm64 环境。

**⚠️ 该文件尚未出现在 GitHub 上**：写 `.github/workflows/` 下的文件要求 token
具备 `workflow` scope，本机凭据只有 `repo` scope，GitHub 对这类路径一律回 404
（Contents API 与 Git Data API 都是）。文件已在仓库里、内容有效，需按
`PROGRESS.md`「阻塞」第一条手动通过网页添加一次，之后 CI 即生效。

两个必须保留的细节：

- `--rerun-tasks`：否则 Gradle 可能 FROM-CACHE 复用旧结果，等于没跑（AGENTS.md
  §2 记录的坑）；
- `-PskipPhotoTests=true`：真值回归台（`RealPhotoMatchTest` /
  `Photo12RegressionTest`）依赖不入库的真实照片素材，CI 无此素材。该 flag 只
  影响 CI，本机照常执行——这是宽场/暗星等修复的唯一真值保护。

## 4. 相机链路：4 平面 → 1 平面

`ImageAnalysis` 原用 `OUTPUT_IMAGE_FORMAT_RGBA_8888`，把 4 个平面逐字节拼成
ARGB Bitmap（800×600 = 192 万次 `ByteBuffer.get()`），而识别链路最终只要灰度
（`LocalStarMatcher` 内部也是 `0.299R+0.587G+0.114B`）——等于先花 4 倍代价搬运、
再转回灰度。

改为 `YUV_420_888` 只读 `planes[0]`（Y 就是亮度），省掉 3/4 的数据搬运与
RGB→灰度转换。3 个通道写同一 Y 值，数值上与原路径等价（仍是灰度图），
位图类型与旋转路径不变，因此不影响 §0.63 的叠加对齐。

节流间隔从硬编码 5000ms 改为按核数自适应（≤4 核 → 8000ms）。

**未验证**：真机行为。YUV 路径的 stride/旋转需在设备上确认（见 §5）。

## 5. 在线客户端加固

| 项 | 原状 | 现状 |
|---|---|---|
| 服务器地址 | 任意 URL，无校验 | 强制 HTTPS（本地回环除外），否则构造器抛错并提示用户 |
| 轮询间隔 | 固定 4s，最长 240s 打满 60 次请求 | 指数退避 2s → ×1.5 → 上限 15s |
| Retry-After | 未读 | 读取并优先采用（限流后知道该等多久） |
| waitForJob 超时 | 函数体内魔法数 120_000 | 提为常量 `WAIT_FOR_JOB_TIMEOUT_MS` |
| 网络错误 | 直接抛 | 自动重试一次（弱网改善明显） |
| 429/503 | 当作一般失败 | 识别为「服务繁忙」并给出可重试提示 |
| 重复提交 | 无保护 | 以 (路径, 大小, mtime) 去重，在途时拒绝重复提交 |

`PlateSolveClient` 构造器可能抛错，`StarSolver` 调用点已补 `try/catch` 转为
进度提示，不会让整个求解流程异常退出。

## 6. 调试开关收口

`LocalStarMatcher` 的 6 个调试开关（`debugForceVoteThreshold` /
`debugForceCatalogMag` / `debugCandidateCap` / `debugMinAligned` /
`debugMinAlignRate` / `debugDisableScored`）此前散落在算法各处，
其中 `debugForceVoteThreshold` 是 **public var**——任何模块可写、无标注、无日志，
误写会静默改变识别行为。现全部收为 `internal` 并在顶部集中注释说明。

**字段名刻意保持不变**：离线验证台（`C:\dev\harness` 的 `Sweep` / `ScoreDetail` /
`FailCost` 等）用 `getDeclaredField("debugXxx")` 反射读写，改名会让它们失效。

未做「按天区自适应星等域」——那依赖内角索引先落地（见 §7）。

## 9. 遗留

- **相机 YUV 路径未经真机验证**：stride 与旋转需设备确认。回退成本低
  （改回 `RGBA_8888` + 旧函数即可），但真机上更省 CPU 是确定的。
- **nova API Key 轮换**（PROGRESS「阻塞」第一条）：需开发者在 nova 网站操作，
  代码侧无需改动（已走 `NOVA_API_KEY` 环境变量注入）。本次新增的 gitleaks CI
  可防止此类凭据再次进入公开历史。
- **索引内存释放接口**（11MB 常驻）：需先解决 §0.65 的 `solve_thread_leaked`
  （detach 线程仍在使用索引，此时释放会段错误），即把泄漏标志改为按 solver
  实例记录。顺序不能反。
- **宽场投票轮根因**（内角索引）与**按天区自适应星等域**：算法主项，未动。
- **用户数据回传通道**：与隐私定位有张力，需拍板。
