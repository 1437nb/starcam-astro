# 验证报告增补：§0.49 AR 实时星图 v1.5.35

## 一、概述
把相机取景页的"实时认星"从**每 5 秒盲解一帧**升级为 **AR 实时星图**：
手机传感器（旋转矢量）直接驱动全天星图投影，星座连线/星名/梅西耶标注
随手机转动以 ~60fps 跟手移动，指哪看哪、零延迟；周期求解器降级为
**校准器**——每 5 秒解算成功时把真解中心与传感器预测中心的偏差作为
屏幕平移量反馈给 AR 叠加，抵消磁力计漂移。

## 二、数学模型（纯 JVM 可单测）

1. **恒星预计算**：8419 星表中 mag ≤ 5.2（约 2000 颗，`AR_MAG_LIMIT`）与
   47 个梅西耶天体 → 天球单位向量 v = (cosδcosα, cosδsinα, sinδ)，启动时一次性构建。
2. **赤道 → 东北天旋转矩阵 A**（由恒星时 LST 与纬度 φ 构成，行主序）：
   - E = −sinLST·x + cosLST·y
   - N = −sinφcosLST·x − sinφsinLST·y + cosφ·z
   - U = cosφcosLST·x + cosφsinLST·y + sinφ·z
   几何闭合校验：天顶 (δ=φ, H=0) → (0,0,1)。
3. **相机投影**：camera 坐标 = (v·right, v·up, v·axis)，针孔投影
   screen_x = cx + f·(v·right)/(v·axis)，screen_y = cy − f·(v·up)/(v·axis)，
   f = (w/2)/tan(FOV/2)；v·axis ≤ 0.08（身后/贴边）剔除。每星仅 9 次乘加。
4. **求解器校准**：把已解中心的单位向量投影到屏幕，得到与画面中心的像素差，
   整图平移——每帧 1 次额外投影，精确修正中心漂移（不修正尺度，尺度由 FOV 滑块校准）。

## 三、模块落地

1. **`astro/ArSkyProjector.kt`（新建）**：预计算向量 + `project()` 输出
   `ProjectedSky`（可见 Star2D/Line2D/Label2D/Messier2D，与 StarChartOverlay
   类型完全一致）；连线用预分配 `visibleIdx` 数组 O(1) 回查目录下标，零逐帧大分配。
2. **`util/DeviceOrientationTracker.kt`**：`DevicePointing` 增加相机三轴基
   `right/up/axis`（设备→东北天旋转矩阵列向量，axis = −Z 列，与光轴一致）。
3. **`ui/camera/CameraScreen.kt`**：
   - 顶栏 🌌 AR 开关（持久化 `arLiveStarMap`，默认开）；
   - PreviewView 改 `ScaleType.FIT_CENTER`（整幅可见、比例真实——AR 对齐前提）；
   - AR Canvas：`withFrameNanos` 对齐 vsync 的重绘节拍，姿态从 AtomicReference
     直读（避免传感器 60Hz 触发的状态重组风暴）；按 4:3 流假设计算 FIT 显示矩形，
     canvas save/clip/translate 后复用 **LayeredRenderer.draw** 绘制
     （与结果页样式严格一致，自动适配夜视红）；
   - 每 5 秒求解器继续运行：AR 开启时不再渲染旧位图叠加（防双重绘制），
     成功 → 更新校准向量 + 🎯 角标 + 识别星座标签；
   - FOV 校准滑块 40°~90°（持久化，拖动结束才写盘）；
   - 未就绪友好提示：等待传感器 / 需要定位 / 请朝向星空。
4. **`data/SettingsRepository.kt`**：`arLiveStarMap` / `arFovDeg`（默认 62）。
5. **`ui/I18n.kt`**：`I18n.Ar` 全套中英文案。

## 四、已知限制（诚实声明）
- 预览流按 4:3 假设计算显示矩形（CameraX 默认）；个别 16:9 流设备边缘略有偏差，中心仍准确。
- FOV 为滑块手动校准（默认 62° 典型主摄）；相机2 精确标定（LENS_FOCAL_LENGTH +
  SENSOR_PHYSICAL_SIZE）留作后续增强。
- 磁力计漂移在两次校准之间（≤5s + 求解失败时）以开环精度运行。
