## 2. 失败照片解剖

### 2.1 4963：真值表错误（交叉验证实锤）

- 解出 ra=78.70/dec=20.85/fov=77.2/inliers=27，被旧真值 (73.4, 19.1) 判 FALSE-POSITIVE（差 5.3°）。
- §0.30 早已标注"天区存疑"：旧官方 0.2° 解物理上不可能（0.3″/px），当时按旧官方窗口计入判定。
- **决定性实验（DiagCrossCheckTest 照片间交叉验证）**：4963 与 4974（御夫座，官方已锚定）解出的 WCS 把各自检测星点反投影到天球，**双向重合 23/64 颗，中心距仅 11.59°**——4963 拍的确实就是 4974 那片冬季亮星天区；与 4984/5068 也各有 21-23 颗重合。自研解即真值。
- 处理：真值表 4963 修订为 Truth(78.70, 20.85, 77.2)。

### 2.2 5031：欠曝 + 阈值下限卡死（弱星轮修复）

- 整图最亮星仅 498（正常照片 700~7000），检测只出 32 星；`anchor20=39` → adaptive 阈值 = max(60, 39×0.35) = **60**，把弱星全踢出投票（work=13），投票对数仅 4。
- **轨迹扫描**（阈值 25~50）：单候选投票 10~13 内点真解浮现（ra≈13.6/dec≈71.1/fov≈76，与真值 (13.4,71.0,76.0) 吻合）。
- 修复：match 新增**弱星轮**——主通道（含多候选轮）无解时，用 `weakT = max(25, anchor20×0.25)` 单候选重投一轮。**注意用单候选而非多候选**：multi 在低阈值下噪声敏感（25/35 时 NULL，仅 30/40 偶然过），单候选稳定 10-13 内点。
- 结果：5031 → TRUE-SOLVE（inliers=10）。

### 2.3 5087/5092：左上角灯光/月亮伪影（亮源掩蔽修复，§0.43b）

- 第一轮排查得出"月亮特写、物理不可解"的**错误结论**（见 §2.3 旧版说明）：灰度统计显示 5087 高亮像素 96% 挤在左上象限、旋转网格投影任何天区只匹配 2-5/64 颗，据此误判画面主体是亮源。
- **用户指正后重新实验**（掩蔽亮源再解算）推翻旧结论：掩蔽区外其实有大量真实星点（5087 有 1296 个、5092 有 2638 个候选像素，比成功照片 5068 的 744 个还多）——亮源伪影制造了海量假三角形票，把真票淹没。
- **掩蔽实验**（60×60 窗口均值 > mean+6σ 判为亮源区）：
  - 5087：提星前置零 / 星点过滤两种方案都解出 **SOLVED ra=349.76/dec=24.17/fov=76.3/inliers=16**；
  - 5092：星点过滤方案解出 **SOLVED ra=349.72/dec=24.20/fov=76.1/inliers=13**；
  - 解出天区与真值表 (351.2, 24.3) 吻合（差 1.4°，TRUE 窗口内）——**真值表一直是对的，5087/5092 就是飞马座星空**。
- 修复：detectStarsGray 末尾新增亮源掩蔽——`maskBrightSource()` 用前缀和 O(n) 计算 60×60 窗口均值，标记 > mean+6σ 的网格，剔除落在掩码内的检测星点。正常星空掩码为空，零副作用（合成场/网络图回归实测无影响）。

## 3. 实现变更

### LocalStarMatcher.kt
1. `votePairs` 增加 `multi` 参数（默认 false）：每颗照片星最多取 top-3 个 v≥2 候选（原只有第 1 名），供稀疏场重投用。
2. `match()` 无解时两级补充轮：
   - **多候选轮**（§0.43a）：`t1` 阈值 + multi 重投；
   - **弱星轮**（§0.43b）：`weakT = max(25, anchor20×0.25)` 单候选重投（救欠曝/暗场）。
   - 两级都仅在 `best == null` 时启用；有解路径完全不动；伪解由 bestCandidate 的 inliers≥6 / plausibleFov(0.05~180°) / skySpanConsistent 门槛把守。
3. **亮源掩蔽（§0.43b）**：`detectStarsGray` 末尾新增 `maskBrightSource()`——前缀和 O(n) 计算 60×60 窗口均值，窗口均值 > 全局 mean+6σ 的网格标记为亮源区，剔除落在其中的检测星点（灯光/月亮伪影）。正常星空掩码为空，零副作用。
4. 新增调试钩子（不影响生产）：`debugForceIndexMag`（索引域开关）、`debugSolveTrace()`（解算轨迹）、`fitAndVerify` 改 internal。

### Photo12RegressionTest.kt
- 4963 真值修订（附交叉验证说明）；5087/5092 真值注释更新为亮源掩蔽后可解。

## 5. 已知限制与后续

1. 补充轮使"无解照片"识别耗时增加（RealPhoto 负例套件体现）；掩蔽修复让 5087/5092 类照片回到主轮快速解，整体耗时可接受。若后续嫌慢可对补充轮加时间预算控制。
2. **亮源掩蔽的阈值语义**：mean+6σ 的 60×60 窗口判定对"柔和光晕/大面积低对比亮区"可能漏判（如薄云下的月亮），对"银河/极光"等大面积弱亮结构不会误掩（远低于 6σ）。若真机遇到月亮大光晕照片解不出，可把窗口缩到 40 或 σ 降到 4 再验证。
3. 索引域放大（mag≤5+）实验因构建耗时爆炸（>12min 单张）放弃——索引域 4.0 维持现状，飞马式极稀疏场依赖多候选轮兜底。
4. 多候选轮对"纯伪星点"照片（如无星空的地面照）应无解——补充轮门槛足够严格（实测验证）。
