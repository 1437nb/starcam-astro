## 2. 核心架构设计

### 2.1 为什么采用响应式纯 Kotlin 双语字典而不是覆写 Context
- **稳定性经验**：
  此前尝试在 Compose 顶层通过 `context.createConfigurationContext()` 覆写 `LocalContext provides localizedContext`，导致 `rememberLauncherForActivityResult` 向上查找 Activity 时由于获取到的是普通 `ContextImpl` 而抛出 `IllegalStateException` 引发启动秒崩。
- **纯 Kotlin 响应式方案的优势**：
  - 零系统 Context 欺骗，完全保留原生的 `ComponentActivity` 宿主，根除闪退风险；
  - 集中管理在 `ui/I18n.kt` 中，底层依赖 Compose `mutableStateOf`（`LocaleState.isEnglish`）；
  - 当用户在「设置」中切换语言时，整棵 Compose 树秒级重组并重取对应语言文本，切换体验丝滑无感。
