# 验证报告增补：§0.63 修复叠加连线漂移（切平面原点错位）v1.5.53

## 一、问题（用户 2026-09-14 报告，延续 §0.61/§0.62）

用户照片在 v1.5.52 下**已能识别**，但叠加的星座连线错位：

> "确实是识别出来了，但线连错了，两个线之间的连接没有星，有漂移"

即：星座连线整体相对星点偏移，连线端点落不到星上。

## 二、量化：与独立真值的偏差

用 §0.62 取得的 nova 真值（2200×1650 帧：RA 0.6760° / Dec 23.2037° /
121.630″/px）作参照，把同一批星表星分别用自研解与真值投影到像素，比较偏差：

| 指标 | 修复前 |
|---|---|
| dx 均值 / 标准差 | −0.9 px / 6.7 px |
| dy 均值 / 标准差 | −2.6 px / 4.9 px |
| **平均距离偏差** | **6.0 px** |
| **最大距离偏差** | **23.0 px** |
| 比例尺 | 122.753″（真值 121.630″，**偏 0.92%**） |

分 3×3 网格看偏移形态（关键证据）：

```
格(0,0) dx= +2.2 dy= +0.2      格(1,0) dx= +0.7 dy= +0.5      格(2,0) dx= -0.5 dy= +0.0
格(0,1) dx= +5.5 dy= +0.5      格(1,1) dx= +1.1 dy= -0.9      格(2,1) dx= -5.1 dy= -0.8
格(0,2) dx=+18.8 dy=-13.9      格(1,2) dx= -3.1 dy= -8.3      格(2,2) dx=-12.3 dy=-11.1
```

**中心几乎为零、越靠边缘越大** —— 这是比例尺/畸变型的系统误差，不是随机噪声。

## 三、根因：切平面原点不在图像中心

匹配器的模型是「像素 → 切平面」的**相似变换**（4 自由度），
而照片本身是关于**图像中心**的 gnomonic 投影。这个映射只有在
**切平面原点 = 投影中心（图像中心）** 时才严格成立。

原实现把切平面原点取在**星表星的平均 RA/Dec**（`fitPairs` 的默认行为），
宽场下这个点可以偏离画面中心好几度（本例偏约 3°），于是整场带上了
一个相似变换**吸收不掉**的畸变。

用真值在 Python 台做对照实验（同一批星、同一拟合流程，只改原点）：

| 切平面原点 | 比例尺 | 平均误差 | 最大误差 |
|---|---|---|---|
| A：星表星均值（原行为） | 121.561″ | **14.13 px** | **44.89 px** |
| B：真实图像中心（理想） | 121.652″ | **0.16 px** | 0.33 px |
| C：两遍迭代 | 121.723″ | 1.74 px | 5.22 px |

迭代收敛很快，第 4 遍即达到 0.17 px（与理想原点持平）。

**另一处连带缺陷**：`solve.raDeg/decDeg` 用 `tanInverse(refined.tx, refined.ty, ...)`
计算 —— 把模型的**平移量**当中心，只有在原点恰为图像中心时才等价。
实测该值与 WCS 表达的图像中心差 **0.38° / 1.07°**（约 65 px），
导致结果页显示的坐标偏移（渲染始终用 WCS，故只影响显示数值）。

## 四、修复

1. **切平面原点迭代到图像中心**：精拟合后重复 4 轮
   「用当前 WCS 反推图像中心天球坐标 → 以该点为新原点重新拟合」。
2. **`refineWcs(fixOrigin = true)`**：收敛轮里只精化 `(a,b,tx,ty)`，
   把原点钉住。**这一步不可省** —— 早期版本让 GN 把原点当自由参数优化，
   它会收敛到"该模型下残差最小"却并非图像中心的位置，等于没修
   （实测仍是 6.0 px 偏差）。
3. **`solve` 中心改由 WCS 反推**：`finalWcs.fitsPixelToSky(w/2+0.5, h/2+0.5)`，
   与渲染同一来源，二者永不失配。

## 五、验证

| 项 | 修复前 | 修复后 |
|---|---|---|
| 平均偏差（vs nova 真值） | 6.0 px | **1.7 px** |
| 最大偏差 | 23.0 px | **4.0 px** |
| 比例尺 | 122.753″（+0.92%） | **121.923″（+0.24%）** |
| **内点数** | 15 | **25**（+67%） |
| `solve` 中心与 WCS 中心一致性 | 差 0.38°/1.07° | **完全一致** |
| CRPIX 位置 | 偏离图像中心 | **图像中心 (1100.5, 825.5)** |

内点数从 15 涨到 25 说明拟合质量实质改善（精度提升让更多星落入内点门限）。

回归（全语料 n=60）：

| 样本 | 结果 |
|---|---|
| 用户南宁照片 | SOLVED inl=25 scale=121.92″ |
| apod4（北斗，34°） | SOLVED inl=11 scale=171.09″（真值 170.6″，偏差 0.5″） |
| apod1 / apod2 / apod3 / apod5 / pleiades / m44×2 | **全部 UNSOLVED**（假阳性对照保持） |
| 12 张离线演示照片 | **全部解出**，多张内点提升（5040: 42→48、5092: 11→22、5031: 8→10） |
| 全量单测 | **150 项 0 失败** |

注意 5092 在修复前会失败，精度修复后转为解出 —— 附带收益。

## 六、遗留

- 残余偏差 1.7 px（约 0.24% 比例尺误差）来自检测星点的质心噪声与
  星表位置的精化程度，属可接受范围（连线宽度远大于 2 px）。
- 若需进一步压缩，可在检测端做 PSF 加权质心或用更多内点迭代 ——
  收益有限，暂不做。
