## 1. 变更背景与目标

在 Sprint 3 实现了 `SolveStep` 解耦与双引擎并发竞速（`raceSteps`）后，`LocalStarMatcher` 内部原有的对象级可变状态与全局锁 `synchronized(solveLock)` 成为了多线程并发求解的最后瓶颈：
1. **全局锁限制多路并发**：原 `LocalStarMatcher.kt` 中维护了 `cachedScoreTable`、`cachedGrid` 以及 `catalogMag`、`scoredCap`、`lastDiagnostics` 等全局状态，所有求解请求必须在 `synchronized(solveLock)` 块内串行执行；批量识别或多路测试无法获得多核并行红利。
2. **AR 预览宽高比硬编码（审计 B14）**：`CameraScreen.kt` 内硬编码了 `3f / 4f`（两处），当相机硬件返回 16:9 或其它视口比例时，AR 投影画面与取景画面出现黑边偏移或拉伸变形。
3. **失败现场落盘性能（§4.5）**：`SolveLogStore.kt` 原有 `input.gray.gz` 采用逐个像素 `writeFloat` 循环写入，每次识别失败落盘产生数万次小 I/O 调用，拖慢响应。
4. **Locale 浮点格式化隐患（§3.5）**：日志与中间状态字符串使用 `"%.1f".format(x)`，在德语、法语等地区系统下会产生逗号小数（如 `1,5`），导致字符串拆分与日志解析异常。

## 2. 核心架构设计与重构实现

### 2.1 MatchContext 求解上下文与无锁缓存（§4.3）

在 [LocalStarMatcher.kt](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/LocalStarMatcher.kt) 中：
- **引入 `MatchContext` 数据类**：
  封装单次求解全生命周期的全部状态与参数，包括：
  - `idx`: 星表三角索引
  - `mag`: 当前选定星等阈值
  - `tbl`: 打分表引用
  - `grid`: 空间网格哈希引用
  - `scoredCap`: 打分三角形容量
  - `diagnostics`: 单次求解独立的诊断快照构建器
  - `usedFallback` / `deepRejectedReason`: 状态标记
- **星表网格与打分表转为 ConcurrentHashMap 缓存**：
  ```kotlin
  private val scoreTableCache = ConcurrentHashMap<Float, ScoreTable>()
  private val catGridCache = ConcurrentHashMap<Float, Map<Int, List<StarEntry>>>()
  ```
  通过 `computeIfAbsent(mag) { ... }` 实现线程安全按需构建并长期缓存，彻底移除旧的 `synchronized(this)`。
- **彻底移除 `solveLock` 全局锁**：
  `matchWithDiagnostics` 与 `matchInternalContext` 不再持有任何全局互斥锁，多线程并发求解（如批处理、双实例竞速）完全独立并行，互不串台、互不阻塞。

### 2.2 AR 预览宽高比纯函数自适应（§3.2 审计 B14）

在 [CameraMath.kt](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/CameraMath.kt) 中提取纯函数：
```kotlin
data class FitRect(val left: Float, val top: Float, val width: Float, val height: Float)

fun computeFitCenterRect(
    containerWidth: Float,
    containerHeight: Float,
    streamAspectLandscape: Float = 4f / 3f,
    isPortrait: Boolean = true
): FitRect
```
- 计算在指定容器尺寸与流横向宽高比下，按照 `FitCenter` 模式居中填充的矩形区域（自动计算上下或左右黑边偏移）。
- [CameraScreen.kt](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/ui/camera/CameraScreen.kt) 全面替换硬编码的 `3f / 4f`，使用 `CameraMath.computeFitCenterRect` 计算视口区域，确保 AR 投影矩阵与相机取景框完美对齐。
- 在 `CameraMathTest.kt` 中补充竖屏 4:3、横屏 4:3 与横屏 16:9 的高精度单测。

### 2.3 失败现场落盘优化（§4.5）

在 [SolveLogStore.kt](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/data/SolveLogStore.kt) 中：
- 将逐浮点数循环写入替换为 32KB `ByteBuffer` 缓冲块传输：
  ```kotlin
  val buffer = ByteBuffer.allocate(32 * 1024).order(ByteOrder.LITTLE_ENDIAN)
  for (v in gray) {
      if (!buffer.hasRemaining()) {
          gz.write(buffer.array(), 0, buffer.position())
          buffer.clear()
      }
      buffer.putFloat(v)
  }
  if (buffer.position() > 0) {
      gz.write(buffer.array(), 0, buffer.position())
  }
  ```
  写盘速度提升数十倍，彻底消除主线程或协程短时卡顿。

### 2.4 全局浮点格式化 Locale.ROOT（§3.5）

- 在 `LocalStarMatcher.kt`、`CameraMath.kt`、`PlateSolveClient.kt` 等各处，所有 `String.format` 与 `String.format("%.*f")` 均显式指定 `Locale.ROOT`，杜绝国际化环境下的逗号小数解析崩溃。
