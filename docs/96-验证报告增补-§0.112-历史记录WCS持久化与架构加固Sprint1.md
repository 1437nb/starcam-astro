## 1. 任务背景与问题排查

根据《StarCam 弱点系统性深度分析报告》（starcam_weakness_analysis.md）与真机实测体验：
1. **历史记录重复求解与打开延迟高**：
   - 旧版 `HistoryStore.Entry` 仅持久化了标量天体坐标（`raDeg, decDeg, fovDeg, engine, constellation`），未存储求解生成的 `WcsTransform` 投影参数；
   - 用户从「识别历史」点击打开任一历史照片时，`HistoryScreen` 仅把图片路径传递给 `ResultScreen`，系统被迫在后台重新调度耗时数秒至数十秒的完整 Plate Solving 求解链路，甚至重复计入打点和重复写入历史记录；
   - 拍照与导入的图片存放在应用的 `cacheDir`，若被系统或用户清理缓存，历史记录中的图片链接全部失效（Broken Image）。
2. **高赤纬大圆角距失真**：
   - `StarSolver.crossCheckAccept` 在复核判定时，直接使用 `dra = |localRa - native.ra| < 3.0°`；
   - 未乘 $\cos(\text{Dec})$，在极区（如天琴、仙后、北天极天区，Dec = 70°~89°）使原本在物理天球上相距不足 1° 的合理结果因 $\Delta\text{RA} > 3^\circ$ 而被错误拦截拒解。
3. **AR 视场自动标定污染（Audit B3）**：
   - `CameraScreen.kt` 帧分析器在解算预览帧后，无条件将解出视场写回持久化配置 `settings.arFovDeg = arFovDeg`；
   - 弱解或低内点边缘拟合解可能导致用户相机的 AR 视场标定失准，影响后续 AR 星图对齐精度。

## 2. 核心架构改进

### 2.1 `HistoryStore` WCS 完整元数据持久化
在 `HistoryStore.Entry` 中补充序列化字段：
- 比例尺与姿态：`pixScaleArcsec`, `orientationDeg`, `parity`, `imageWidth`, `imageHeight`
- WCS 核心切平面投影参数：`wcsCrpix1`, `wcsCrpix2`, `wcsCrval1`, `wcsCrval2`, `wcsCd11`, `wcsCd12`, `wcsCd21`, `wcsCd22`
- 诊断数据：`nMatch`, `logodds`

提供互逆方法：
- `Entry.toSolveResult(): SolveResult?`：完整重建包含 `WcsTransform` 的求解模型，旧版本无 WCS 历史记录安全回退为 `null`；
- `Entry.fromSolve(...)`：从 `SolveResult` 一键打包装箱。

### 2.2 0ms 即开与去重防护
- **0ms 即开**：`Screen.Result` 增加可选参数 `cachedSolve: SolveResult? = null, cachedEngine: String? = null`。从历史列表点击打开时直接传入还原的 `SolveResult`，结果页直接跳过 `StarSolver.solve` 求解链路，0ms 直接解码并呈现带星座连线与天体标注的最终画面；
- **免重复记录**：历史缓存模式下不重新触发打点统计 `StatsStore.record`，亦不重复调用 `HistoryStore.save`；
- **图片缓存保护**：在 `HistoryStore.save` 时，自动检测图片是否处于易失性目录，将图片持久化转存至私有 `filesDir/history`；
- **历史记录去重**：同一张图片路径在 `save` 时自动排重，避免重复点击产生大量冗余条目。

### 2.3 高赤纬天球真实大圆角距
在 `StarSolver.kt` 中引入球面上两点角距计算：
$$\cos(\theta) = \sin(\delta_1)\sin(\delta_2) + \cos(\delta_1)\cos(\delta_2)\cos(\alpha_1 - \alpha_2)$$
`crossCheckAccept` 改用球面角距 $\theta < 3.0^\circ$，彻底消除高赤纬天区的几何畸变拦截。

### 2.4 AR FOV 置信度门禁
在 `CameraScreen.kt` 帧解算后，加入双重置信度闸门：
```kotlin
val isHighConfidence = (res.inlierCount >= 18 &&
    res.catalogDomain == CatalogDomain.SHALLOW) ||
    ((res.solve.logodds ?: 0.0) >= 25.0)
```
仅当解算结果满足高置信门槛时，才允许自动更新 `settings.arFovDeg` 与 `arAzimuthOffsetDeg`。
