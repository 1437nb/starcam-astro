## 1. 任务背景与问题分析

根据系统性弱点分析报告 P0 问题 2.1 与 2.2：
1. **求解不可取消，后台持续空转占用 `solveLock`**：
   - 旧版 `ResultScreen` 在 `LaunchedEffect` 中调用 `StarSolver.solve`；
   - 用户按返回键或离开页面仅取消了外部协程外壳，底层 `LocalStarMatcher` 打分轮与投票轮以及 `StarSolver` 内部各步骤均为同步阻塞执行，无法感知取消；
   - 更严重的是：计算期间一直占用进程级 `LocalStarMatcher.solveLock`，导致用户切换到下一张照片时发生连锁排队阻塞；且 `LoadingContent` 界面缺乏手动「取消」按钮。
2. **串行接力无全局总预算，最坏耗时恶性叠加**：
   - 官方盲解分为传感器先验、天顶先验、分段盲解两段（16s + 12s）、降采样重试两段（10s + 10s）、本地匹配与在线兜底；
   - 缺乏全局总时间死线（Deadline），在多引擎均未命中或弱网场景下，耗时动辄累加至 60s~120s；
3. **`demoPhotoFov` 缺乏路径白名单隔离**：
   - 普通用户若在相册或导入名为 `photo5031.jpg` 的照片，会被错误套上 76° 广角先验。

## 2. 核心方案与实现

### 2.1 `SolveToken` 取消令牌全链路贯穿
- **令牌抽象**：实现 [`com.starcam.astro.astro.SolveToken`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/SolveToken.kt)，具备轻量原子取消标志 `isCancelled` 与 `check()` 检测；
- **底层循环快速熔断**：
  - 在 [`LocalStarMatcher.kt`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/LocalStarMatcher.kt) 的 `matchLocked`、`matchInternal`、`votePairs` 以及 `scoredRound`（打分轮每 64 组候选）注入 `token?.check()`，毫秒级快速终止并安全释放 `solveLock`；
  - 在 [`StarSolver.kt`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/StarSolver.kt) 的引擎步骤循环中插入 `coroutineContext.ensureActive()` 与 `token.check()`；
  - 规范异常传播：所有底层 `catch (e: Throwable)` 增加 `if (e is CancellationException) throw e`，杜绝取消异常被错误吞没为求解失败。
- **UI 生命周期接管**：
  - 在 [`ResultScreen.kt`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/ui/result/ResultScreen.kt) 绑定 `DisposableEffect(solveToken) { onDispose { solveToken.cancel() } }`，退出页面时即刻熔断后台求解；
  - 顶栏返回键触发 `solveToken.cancel()`；
  - `LoadingContent` 界面增加显式「取消」按钮，点击立即终止并安全返回。

### 2.2 全局总时间预算（Global Solve Deadline）
- 在 [`SettingsRepository.kt`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/data/SettingsRepository.kt) 增加 `solveBudgetSec: Int`（默认 30 秒，范围 10~120 秒）；
- 在 [`StarSolver.kt`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/StarSolver.kt) 入口计算统一死线 `deadlineMs = System.currentTimeMillis() + budgetSec * 1000`；
- 每个子引擎步骤开始前，计算剩余时间 `remSec = (deadlineMs - now) / 1000.0`：
  - 若 `remSec <= 0.5s`，立即跳出引擎循环，记录预算耗尽日志并给出诊断；
  - 各分段盲解与先验轮的执行超时时间动态收缩为 `minOf(stepTimeout, remSec * 0.9)`，严格杜绝总耗时超时。

### 2.3 `demoPhotoFov` 路径安全隔离
- 在 [`StarSolver.readFovDeg`](file:///c:/starcam/code/app/src/main/java/com/starcam/astro/astro/StarSolver.kt) 中增加来源白名单校验：仅当图片路径属于 `offline_photos`、`realphotos`、`testdata` 或离线演示目录时才应用已知真值先验；普通用户相册（DCIM/Camera、Download 等）即使同名也绝不污染。
