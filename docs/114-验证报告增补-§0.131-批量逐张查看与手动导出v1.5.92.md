# §0.131 批量逐张查看与手动导出（v1.5.92）

日期：2026-11-02。versionCode：112；updateDesc：`batch-photo-review-export`。

## 需求与最终行为

开发者要求批量识别完成后，每张图片都能像单张识别一样打开，选择是否导出带标记的图片；并明确选择「逐张查看，手动选择导出」。

- 批量识别只执行识别和保存历史记录，不再默认生成、写入系统相册的标注图。
- 完成后列表展示缩略图、文件名和每张状态；成功项提示「查看结果 / 选择导出」，失败项提示「打开并单独重试」。
- 成功照片进入现有 `ResultScreen`，使用批量缓存的 SolveResult/WCS，免重复求解；支持图层开关、天体卡片、全屏缩放，以及「仅星座连线」「保存当前标注」。
- 不点击保存就不会向系统相册导出。成功识别仍会记录在识别历史中。
- 返回详情上一级仍是同批列表，保留结果与列表滚动位置。屏幕配置变更由 ViewModel 保留批量数据，避免重启批任务。
- 失败照片打开后走单张识别流程重试。列表统计表示原批次结果；详情中的再次识别不会改写原批次统计。

## 实现与资源边界

1. `BatchViewModel` 承担批任务与元数据存储，普通设备保持最多两路并发，低内存设备一路；主线程领取队列和发布状态，IO 线程读图与求解。
2. `BatchOutcome.Solved` 表示「已识别、等待用户决定导出」，识别计数增加，导出计数不增加。已有的自动保存结果类型及其计数保护保留。
3. `BatchScreen` 将完整单张结果页作为批次内部子页；返回不卸载整个批次，不会因为返回列表再次批量求解。每次新建批次使用独立会话标识，重新选择同组照片仍会启动新任务。
4. 批量结果不持有大位图；每张任务结束释放解码位图和在线返回位图，缩略图复用现有 8 MiB 缓存。
5. 在线结果的 WCS 对应上传图片的像素方向。批量保存该显示基准为私有 cache 中的无损 PNG，详情通过 `cachedDisplayPath` 加载，而原路径继续提供 EXIF 拍摄时间和位置；不会将显示副本写入系统相册。本项只覆盖当前批次详情；此前历史在线结果的方向问题未在本次统一修改。
6. 批量数据为当前应用会话数据，未增加进程被系统杀死后的队列恢复。在线显示副本属于系统可清理的缓存；若被清理，结果页提示无法读取，可单独重试。
7. 版本三处同步至 1.5.92 / 112 / batch-photo-review-export。先构建 Debug，随后按开发者「跑 release」指令完成本地签名 Release；随后按明确推送指令同步源码与文档至 GitHub main；未发布 GitHub Release 与 APK 附件。
