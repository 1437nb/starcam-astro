## 四、真实根因：`plim` 语义误用

`sepDetectStars(bitmap, sigma=2.0)` 的参数语义是「背景 sigma 倍数」，
但 C 层 `extract_stars_impl` 把它**直接写进 simplexy 的 `plim`**：

```c
/* 修复前（astro_bridge.c） */
if (thresholdBgMultiple > 0.0)
    s.plim = (float)thresholdBgMultiple;   // 2.0 直传
```

而 `plim` 的真实语义是**峰值显著度**，simplexy 的检出限公式为
（`simplexy.c` §finding objects）：

```
limit = sigma / (2 * sqrt(M_PI) * dpsf) * plim
```

`dpsf` 默认 1.0 时系数 `1/(2√π) ≈ 0.2822`，即 **plim=2.0 只相当于 0.56σ** ——
检出限**低于噪声水平**。

### 4.1 后果链（用用户照片真实像素验证）

在 `orig.gray`（1649×2200，mean 18.17，sigma≈4.12）上复现 simplexy 的 dmask
（阈值 + 4 邻域连通域标记）：

| 设置 | limit | 过阈像素 | 占比 | 最大连通域 | 超 maxsize=2000 |
|---|---|---|---|---|---|
| **plim=2.0（bug）** | 2.32 | 1,061,698 | **29.27%** | **848,846 px** | **是（88 万）** |
| plim=7.09（修复） | 8.24 | 22,781 | **0.63%** | 55 px | 否 |

**整幅图 29% 的像素被连成一个 85 万像素巨块** → 远超 `maxsize=2000` →
simplexy 判定为「延展天体」（星云/光污染）**整体丢弃** → 真星全丢，
只剩背景估计失效的**图像边界**零碎伪影 → 就是 report 里那 172 颗。

这同时解释了用户的观察：**拉高对比度后背景被拉开，真星相对噪声的信噪比提升，
且不再形成超大连通域，真星才得以检出**。

## 五、修复

### 5.1 C 层：阈值语义换算（`astro_bridge.c`）

```c
/* 修复后 */
if (thresholdBgMultiple > 0.0) {
    double plim = thresholdBgMultiple * 2.0 * sqrt(M_PI) * SIMPLEXY_DEFAULT_DPSF;
    if (plim < 4.0) plim = 4.0;     /* 下限：防止再次跌进噪声区 */
    s.plim = (float)plim;           /* 2σ → 7.09，≈ 上游默认 8.0 */
}
```

### 5.2 Kotlin 层：边界过滤 + 提星质量核验（`StellarSolverNative.kt` / `StarSolver.kt`）

1. **边界过滤**：剔除距图幅 < 16px 的检出（`EDGE_MARGIN_PX`）。
   对正常样本仅损失 2.5~2.9%（正常星本就远离边缘），对失败样本剔除 44% 伪影。
2. **提星质量核验**：SEP 结果与 box-blur 前 30 亮星的重合率 < 30% 时判为不可信，
   **自动回退 box-blur**，杜绝"上游提星退化 → 整个引擎白跑"。
3. **提星诊断入日志**（用户要求"把识别过程记录下来"）：星数、边界剔除数、
   flux 范围、边缘占比、与 box-blur 重合率，全部写入识别日志。
