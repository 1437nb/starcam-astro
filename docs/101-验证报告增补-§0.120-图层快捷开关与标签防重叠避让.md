# 101 · 验证报告增补 §0.120 —— 图层快捷开关与标签防重叠避让

> 版本：v1.5.85（工作区）
> 日期：2026-10-25
> 来源：用户反馈与真实图片缺陷排查：
> 1. 新功能：在图片识别完毕后增加是否在图片上标记星星名字，并可以导出只有星座连线的图片；
> 2. Bug 1：星团 M45（昴星团）与恒星名字（昴宿六 Alcyone）重叠（类似 M42 与伐三）；
> 3. Bug 2：靠边缘的星星名字超出图片画幅边缘（如卷舌二、天船三顶部被裁切，参宿一/二/三左边缘被裁切）。

---

## 1. 缺陷根因分析

### 1.1 M45 与星名直接重叠（Bug 1）
- **根因**：
  - M45 昴星团中心天球坐标为 $(\text{RA } 56.75^\circ, \text{Dec } +24.11^\circ)$；其内部最亮星 Alcyone（HIP 17702 / 昴宿六，mag 2.87）位于 $(\text{RA } 56.87^\circ, \text{Dec } +24.10^\circ)$。
  - 在全景与中等焦段照片中，两者映射至屏幕同一点（欧氏距离仅数像素）。
  - 旧渲染逻辑在 `draw` 中分别无条件在星点右上方固定偏移（$x+7\text{dp}, y-7\text{dp}$）绘制星名，并在梅西耶标记处（$x+10\text{dp}, y-6\text{dp}$）绘制文字标签，两串文字直接重叠打印（显示为「昂M45 昂星团」等难以辨识的乱码）。
  - 同样问题存在于 M42 猎户座大星云中心与梯形成员星（伐三等）。

### 1.2 星名超出图片边界（Bug 2）
- **根因**：
  - `StarChartOverlay.projectStars` 投影全天星表时为保证画幅边缘连线连贯，允许 `marginPx = 140f` 的外扩边界，因此位于画幅外侧（如 $x < 0$ 或 $y < 0$）的恒星 `s.visible` 仍判定为 true。
  - 在 `LayeredRenderer` 绘制时，采用 `canvas.drawText(name, s.x * sx + 7f * density, s.y * sy - 7f * density, p.text)`。
  - Android Canvas 的 `drawText` 纵坐标参数为基线（baseline）：文字高度由 $y + \text{ascent}$（负值，向上）延伸至 $y + \text{descent}$。
  - 若恒星位于画面顶部边缘（如 $y \cdot sy = 8\text{px}$），$y - 7\cdot 2 = -6\text{px}$，且文字顶部为 $-6 - 14 = -20\text{px}$，导致文字整半截被裁切在画幅外。
  - 若恒星位于右侧边缘，横坐标直接溢出 `drawWidth`。

---

## 2. 方案与实现

### 2.1 标签防碰撞避让与边界安全收敛（`LayeredRenderer.kt`）

1. **可见性与梅西耶近邻过滤**：
   - 过滤条件升级：恒星不仅需满足 `s.visible && s.entry.mag <= 3.2`，其坐标必须严格位于画布内 `s.x * sx in 0f..drawWidth && s.y * sy in 0f..drawHeight`，画幅外恒星一律不标名字。
   - 当 `flags.messier` 开启时，若恒星与画面中任何可见梅西耶天体中心欧氏距离小于 $28f \cdot \text{density}$（约 56px），自动抑制该星的名字绘制（星团标签已涵盖该天体，符合专业星图惯例）。
2. **绘制顺序与 BoundingBox 占用表**：
   - 调整绘制次序：连线 → 梅西耶深空天体 → 太阳系天体 → 恒星专名 → 星座名称。
   - 引入纯 JVM 轻量级 `BoundingBox(left, top, right, bottom)` 记录已占用区域。
   - 梅西耶天体绘制时，圆圈与文字标签即刻加入占用表，并同样具备右/左翻转与边缘安全收敛。
3. **4 象限候选避让算法（`computeStarNamePlacement`）**：
   - 按恒星亮度升序排序（亮星优先占位）。
   - 对每颗星依次评估 4 个象限候选位置：
     1. **象限 1（右上，默认）**：$(px + \text{offset}, py - \text{offset})$
     2. **象限 2（右下）**：$(px + \text{offset}, py + |\text{ascent}| + \text{offset})$ —— 专门适配顶部边缘恒星（如卷舌二、天船三）；
     3. **象限 3（左上）**：$(px - \text{textWidth} - \text{offset}, py - \text{offset})$ —— 专门适配右边缘恒星；
     4. **象限 4（左下）**：$(px - \text{textWidth} - \text{offset}, py + |\text{ascent}| + \text{offset})$ —— 专门适配右上角区域。
   - 候选位置满足「完全在画幅安全边距 $6f \cdot \text{density}$ 内」且「不与任何已有 BoundingBox 碰撞」即采纳。
   - 若 4 象限均有微小重叠，使用边界收敛坐标；若与深空天体发生严重重叠且非极亮星（$\text{mag} > 2.0$），安全舍弃绘制避免成团污染。

### 2.2 结果页图层快捷开关与仅星座连线导出（`ResultScreen.kt` & `I18n.kt`）

1. **图层快捷 FilterChip 栏**：
   - 在识别结果页照片下方显著位置增加横向滑动的 `FilterChip` 开关条：
     - `星星名字`（`LayerFlags.starNames`）：点击即刻在画面上显示/隐藏所有恒星名字；
     - `星座连线`（`LayerFlags.lines`）；
     - `星座名称`（`LayerFlags.constellationNames`）；
     - `深空天体`（`LayerFlags.messier`）；
     - `月亮与行星`（`LayerFlags.planets`，检测到太阳系天体时可见）。
   - 开关即时响应，实时重绘预览画面及放大查看器。
2. **纯净星座连线图导出**：
   - 在 `LayerFlags` 中预置 `LINES_ONLY` 常量（仅 `lines = true`，其余全为 `false`）。
   - 在相册保存区域提供双按钮操作：
     - `OutlinedButton: 📐 仅星座连线`：一键导出背景星空 + 纯净星座连线的照片，无任何文字或圈圈干扰；
     - `Button: 💾 保存当前标注`：根据当前 FilterChip 挑选的任意图层组合生成并保存照片。

### 2.3 预览图与放大查看器图层状态一致性修复（`v1.5.86`）

- **现象**：在预览图仅勾选星座连线与星座名称，点进大图后发现依然显示了星星名字与深空天体等所有图层。
- **根因分析**：
  1. `StarPhotoOverlay` 原 `pointerInput(Unit)` 闭包未建立对 `layerFlags` 的依赖，在多次切换图层后触发点击放大的 `onTap` 闭包仍持有初次挂载时的 `LayerFlags.ALL` 快照，导致传入放大查看器的底图始终全开图层；
  2. `ZoomableImageViewer` 内部使用无 Key 的 `remember { mutableStateOf(initialFlags) }` 与 `annotatedBitmap`，初次渲染后外部状态变化被内部缓存阻断，且缺少 `onFlagsChange` 双向回传回调；
  3. `hitTestObjectAt` 天体点击探测未感应 `flags`，导致未开启星星名字时点击空白星区依然弹出隐藏星星的科普卡片并阻断点击放大；
  4. `ZoomableImageViewer` 浮层菜单缺少「月亮与行星」开关，且异步状态提交时传递了旧状态快照。
- **解决方案**：
  1. `StarPhotoOverlay` 引入 `rememberUpdatedState(onTap)` 与 `rememberUpdatedState(flags)`，`pointerInput` 建立对 `(state, flags)` 的动态响应；
  2. `hitTestObjectAt` 增加 `flags: LayerFlags` 校验，仅对当前启用的图层进行点击命中检测；
  3. `ZoomableImageViewer` 绑定 `remember(initialFlags)` 与 `remember(annotated)`，新增 `onFlagsChange` 回调实现大图与主页图层双向同步；补齐「月亮与行星」开关项。
