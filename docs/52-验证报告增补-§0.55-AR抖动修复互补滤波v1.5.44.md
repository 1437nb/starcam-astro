# 验证报告增补：§0.55 AR 抖动修复（互补滤波）v1.5.44

## 一、问题（真机反馈）
AR 星图静止时星座连线/名字抖动；移动时也有抖动。

## 二、根因
v1.5.40~43 的融合方案在**每次旋转矢量事件（~50ms）把姿态硬性锚定到旋转矢量**：
- 静止时：旋转矢量自身噪声 ~0.1-0.5°，每 50ms 星图被"拽"一下 → 肉眼可见抖动；
- 移动时：旋转矢量（经系统融合，带延迟）落后于陀螺积分，硬锚定产生"回拽"。

## 三、修复：互补滤波（astro/AttitudeFusion.kt，纯 JVM）
单一运行四元数 q（设备→世界）：
- **陀螺仪**（体坐标右乘 dq）负责快速平滑的运动跟踪（快通道）；
- **旋转矢量**只做漂移校正：每次事件按时间常数 τ=0.8s 做 nlerp 缓慢拉回
  （alpha = 1−exp(−dt/τ)，约 0.06/事件）——静止噪声被深度平滑、移动不再回拽；
- 预测外推保持不变（最新角速度 + 24ms）。
`QuatMath` 新增 `nlerp`（含双覆盖翻转处理）。
DeviceOrientationTracker 的 predictedPointing 改为 `fusion.predicted()`；
无陀螺仪设备同样受益（旋转矢量自身也被互补平滑）。

## 四、验证（AttitudeFusionTest 新增 5 项）
- **静止平滑**：±0.3° 等幅交替噪声 100 次，60 事件热身后稳态逐帧抖动 < 0.05°
  （约为噪声峰值的 1/6；调参过程曾用 Python 精确复现算法，确认首事件瞬态
  按 τ 衰减，热身 3τ 后测稳态）；
- **慢校正收敛**：旋转矢量跳变 5°，4 秒内收敛到 <0.5°；
- **快跟踪**：旋转矢量保持旧值、陀螺 90°/s 积分 1s → 90°（移动不回拽）；
- **预测外推**：45°/s × 0.2s = +9°；
- **nlerp 基础**：范数保持、t=0/1 端点、双覆盖翻转。
全量 `testDebugUnitTest` 通过；`assembleDebug` 成功：
`StarCam-v1.5.44-AR抖动修复互补滤波-debug.apk`（仅 debug）。

## 五、真机复测要点
① 静止不动：星图应完全稳定（无 50ms 级"拽动"）；
② 缓慢/快速转动：跟手且无回拽；③ 转动后停住：星图位置与真方位一致
（漂移由旋转矢量慢校正兜底，若感觉校正偏慢可把 τ 调小，一行参数）。
