# 验证报告增补：§0.59 无 GPS 照片的位置兜底 v1.5.49

## 一、背景与目标

真实手机照片的 EXIF 普遍缺项（见 `docs/04`、`docs/05` 坑 #12）：焦距与 GPS 都可能没有。

本 App 三层求解中的**官方引擎天区先验轮**（`StarSolver` 第 2 步）依赖 `ExifPriors.zenith`，
而它要求 **GPS + 拍摄时间同时齐全**——缺任意一项即返回 null，这类照片只能从全天空盲解起步
（12s + 16s 两段），成功率与耗时都明显吃亏。

§0.58 收尾时已记下候选方向：

> 无 GPS 时用当前定位兜底并明确提示用户「位置来源为当前定位，可能不准」。

本版实现该项。

## 二、方案

### 2.1 只在「缺位置」且「有时间」时兜底

兜底不是无条件替换，三条硬边界：

1. **EXIF 定位永远优先**——有则不兜底，绝不被覆盖；
2. **无拍摄时刻则不兜底**——天顶 RA/Dec 由「纬度 + 经度 + 时刻」三者共同决定，
   没有时刻就没有天顶，补位置毫无意义，只会平白引入一个错误前提；
3. **半套 GPS 视为缺失**——EXIF 只写了纬度（或只有经度）时整对补全。

### 2.2 位置来源必须可追溯

新增 `LocationSource` 枚举（`EXIF` / `CURRENT_FALLBACK` / `NONE`）挂在 `ExifPriors` 上，
并暴露 `locationIsFallback` 供 UI 判断。**只要用了兜底，用户就必须看得见**：
求解进度文案与结果页信息面板两处都会标注来源。

## 三、实现

| 文件 | 改动 |
|---|---|
| `astro/ExifPriors.kt` | 新增 `LocationSource` 与 `withFallbackLocation()`；`read()` 标记来源；`solarSystemForPhoto()` 增加 `fallbackLocation` 参数；新增 `needsLocationFallback()` 供调用方预判是否值得取一次定位 |
| `astro/StarSolver.kt` | 官方引擎分支：缺 GPS 且有拍摄时间时取 `LocationHelper.getBestLocation()` 兜底；进度文案与 `nativeDetail` 标注「当前定位先验」 |
| `ui/result/ResultScreen.kt` | `ResultUiState.Success` 增加 `locationIsFallback`；日月行星标注传入兜底定位；`InfoPanel` 显示来源提示 |
| `ui/batch/BatchScreen.kt` | 批量导出的日月行星标注同样支持兜底 |
| `ui/I18n.kt` | 新增 `Result.locationFallback` 中英文案 |

**为何不改 `ExifPriorsReader.read()` 本身**：它是纯函数（只读 EXIF），引入定位会带来
Context / 权限依赖并破坏可测试性。定位由调用方注入，先验对象只负责如实记录来源。

## 四、风险与取舍

### 4.1 两类用途的风险并不对称

- **天区先验**（`StarSolver`）：位置偏差 → 搜索区域偏 → 最多解不出，之后**照常回落**到
  分段盲解。净效果 ≥ 0，只多花一轮时间。
- **日月行星标注**（`solarSystemForPhoto`）：位置偏差会**直接反映成标注偏差**。
  月亮地平视差最大约 1.02°；经度差 1° ≈ 地方恒星时差 4 分钟 ≈ 月亮走 0.04°。
  同城拍摄（经度差 <1°）影响可忽略，跨省（约 10°）约 0.4°，肉眼可辨。

### 4.2 保留「宁可不标也不能标错」的底线

§0.58 定的策略是「缺任意一项即返回空表」。本版**只放宽了位置一项**（允许当前定位兜底），
**时刻一项仍是硬门槛**——因为时刻对日月位置的影响远大于位置（月亮每小时走约 0.55°，
而位置带来的偏差是经度差的 0.04 倍）。UI 明示来源，用户可据此判断可信度。

**未做**：按「照片时间与当前时间的间隔」设阈值（例如超过 24h 就不兜底）。
理由是搜索半径本身很宽（`skyPriorRadiusDeg` 取 60°~85°），对中等位置偏差有容忍度；
而加阈值会让「拍完几天才整理照片」这一常见场景直接失去兜底。留作后续可调项。

## 五、验证

| 项 | 命令 / 方式 | 结果 |
|---|---|---|
| 编译 | `gradle :app:testDebugUnitTest --rerun-tasks` | ✅ 通过 |
| 兜底边界单测 | 同上（`ExifPriorsFallbackTest`） | ✅ 6/6 通过 |
| 全量回归 | 同上 | 149 项：146 通过；3 项因**本机缺测试素材**失败（见下） |
| 真机：缺 GPS 照片 | 见 §6 | 待开发者执行 |

**关于 3 项失败（与本次改动无关）**：`RealPhotoMatchTest`（2 项）与 `Photo12RegressionTest`（1 项）
的失败位置分别是 `RealPhotoMatchTest.kt:50` 与 `Photo12RegressionTest.kt:85`，
两处都是**测试素材存在性断言**（断言语义分别为「测试素材缺失」「12 张回归素材缺失」），
而非识别能力断言。素材候选路径（`C:/starcam-bundle/testdata/...` 与相对 `../../testdata/...`）
在本机均不存在——`C:\starcam-bundle` 在本轮合并**之前**就已不在 C 盘根目录。
将 `PHOTO_DIR` / `PHOTO12_DIR` 指向归档中的素材后复跑，该 3 项**全部通过**，
证明识别能力无回归。

新增 `ExifPriorsFallbackTest`（6 项）覆盖：EXIF 定位不被覆盖、有时间才兜底、无时刻拒绝兜底、
半套 GPS 补全、兜底后可算出天顶、缺 FOV 也不影响兜底。

## 六、遗留

- **真机验证**：需要一张「有 EXIF 拍摄时间、无 GPS」的真实星空照片，在开启定位的条件下确认
  （a）求解进度出现「当前定位先验」；（b）结果页信息面板出现「位置来源为当前定位」提示。
- 可选：设置页增加「允许用当前定位兜底」开关，供用户彻底关闭该行为。
