# 28 · 真机回归清单（v1.5.2 → v1.5.7-dev 累计变更，需实体手机）

> v1.5.2（已真机验证）之后累计 4 个版本的代码变更（识别率优化 §0.30、
> 返回手势 §0.30.5、原图相册 §0.31、导航栈/交叉复核/发布配置 §0.32）
> 均只有 JVM 侧验证，需一轮真机 AutoTest 回归还账。
> 用时约 30~45 分钟。

## 0. 准备

1. 安装：`adb install -r apk\StarCam-v1.5.7-debug.apk`（或 release 版）
2. 照片素材：`adb push testdata\photos12\*.jpg /sdcard/Pictures/test12/`
   （MediaStore 入库后排序按 DATE_ADDED，12 张为同一批源文件即可）
3. 全程保持 logcat 捕获：`adb logcat -c` 后
   `adb logcat STARCAM_TEST:I *:S > C:\dev\device-test.log`

## 1. 识别回归（核心）

```bat
adb shell am force-stop com.starcam.astro
adb shell am start -n com.starcam.astro/.AutoTestActivity --es dir /sdcard/Pictures/test12
:: 等待屏幕显示 ALL-DONE（约 3~6 分钟/12 张）
adb logcat -d -s STARCAM_TEST
```

判定（对照 §0.30 修正后的真值表）：

| 期望 | 说明 |
|---|---|
| 每张输出 SOLVED/FAILED 行 | 行内含 ra/dec/fov/engine 明细 |
| 真解 ≥ 7/12 | JVM 数字（box-blur）是**下界**；真机 SEP 提星应 ≥7 |
| 0 个错误天区 | 任何 SOLVED 的天区/视场须落在 §0.30.2 修正真值窗口内 |
| 5031/5057 允许 FAILED | 已知弱项（欠曝/变焦）；但不应报错误天区 |
| 5087/5092 允许波动 | 新增交叉复核：低内点解会触发官方复核，观察耗时增加是否明显 |

## 2. 交叉复核行为（v1.5.7 新）

观察设置页/结果页进度文案：低内点照片（5087/5092）识别时若出现
"官方引擎求解中（视场 …°–…°）"快速二次出现（≤10s），说明复核已挂载。
无真机无法验证引擎可用性以外的部分，本轮至少确认**不崩、不显著变慢**。

## 3. 手势返回（§0.30.5 + 导航栈 §0.32）

1. 主页 → 识别历史 → 打开某条结果 → **侧滑返回**：应回到**历史列表**（不是主页、不是退出）；
2. 再侧滑：回主页；再侧滑：退出应用（Home 不拦截）；
3. 主页 → 相册（原图）→ 侧滑：回主页；
4. 相机页 → 侧滑：回主页。

## 4. 原图相册（§0.31，HyperOS 重点）

1. 主页点「从相册选择（原图·保留拍摄参数）」→ 首次授权「照片和视频」；
2. 选一张有 EXIF 的日间照片 + 一张星空照：结果页识别时观察进度文案，
   星空照若出现「视场 x°–y°」（非"盲解分段"）即 EXIF 焦距已读到；
   拍摄时开了定位的照片若出现「天区先验」即 GPS 已读到；
3. 拒绝权限后重进：应看到说明页 + 「授予权限」按钮；
4. 多选 ≥2 张 → 「识别所选」→ 应进批量页。

## 5. release 包（§0.32）

`StarCam-v1.5.7-release.apk`（R8 混淆 + 签名）：安装跑一遍 1~4 的关键路径，
确认混淆后无崩溃（重点：星座渲染、离线演示、相册缩略图）。
