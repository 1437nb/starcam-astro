# 验证报告增补：§0.71 修复 2026-09-17 照片识别失败与旧照片回归 v1.5.60

## 一、问题（用户 2026-09-17 报告）

小米 REDMI Turbo 5 Max 新拍星空照片（**竖拍**，`IMG_20260917_204426.jpg`，
1649×2200，秋季四边形天区）在 App 中**识别不出来**；同时 2026-09-12 的旧照片
（南宁，横拍 2200×1650）在修复过程中**从 SOLVED 回归 UNSOLVED**。

用户提供了失败日志 `report.json`（§0.70 识别日志功能产出）与照片原件。
日志形态：172 颗星、`work=0`、打分轮压根没启动 —— 与 §0.64 记录过的
**阈值量纲错配**高度一致，但本报告证实那只是冰山一角。

## 二、真实根因：四层缺陷叠加

逐层二分（git stash A/B + 单变量改动）后确认，本版修复了**四个互相独立的缺陷**：

### 2.1 投票阈值量纲错配（SEP flux vs box-blur，§0.64 的尾巴）

`voteThresholds` 的 900 / 60 / 25 绝对阈值按 box-blur 检测器量纲（典型 top≈4154）
标定，但 App 的 SEP 路径喂入的是 simplexy 的 **flux**（量级 1~100）。
§0.64 只给「头部陡峭判据」加了相对兜底，**阈值本身仍是绝对值**：
主阈值 60 只放进 2 颗星、备用阈值 900 一颗不剩 → 投票轮 `work=0` 空转。

**修复**：三个档位全部改为「占最亮星 top 的比例」（0.2167 / 0.0144 / 0.0060，
按 box-blur 基准 4154 换算，保持既有标定等价）。对 SEP 量纲自动等比缩放。

### 2.2 打分轮 y 轴镜像未处理 → 双 parity（本版发现的回归根因）

打分轮的相似拟合把「切平面坐标（东正、北正）」与「照片像素（y 向下）」直接喂给
`fitSimilarity`，两帧之间差一次镜像。§0.71 早前版本把像素 y 取反后拟合
（对 parity=-1 的照片正确），但**真实照片两种奇偶性都存在**：
旧照片（横拍）parity=+1 需要**不**翻转、新照片（竖拍）parity=-1 需要翻转。
写死单个方向必然让另一类照片全体 0 分 —— 实测旧照片 bestScore 7→5
（差 1 颗不过 6 的下限）、从 SOLVED 回归 UNSOLVED。

**修复**：每个候选三角形把两个方向各拟合一次（3 点拟合很廉价），
**取拟合残差小者**（正确方向 ~0.02°、错误方向 ~6°，分离度 300 倍，无歧义）。
与主路径 `fitAndVerify` 的双 mirror 设计对称。

### 2.3 打分轮胜出模型的切平面原点（打分轮内部迭代到图像中心）

打分轮 `scoreHypothesis` 把切平面原点从「三颗星平均」迭代到「图像中心」后，
胜出候选能对齐 24 颗星（5087 实测，率 0.75 远超 0.20 门槛）——但**展开
`expandHypothesisPairs` 仍在用三颗种子星的平均位置当原点**，宽场外推模型与
打分模型差出整个视场 → 扩展出 0 对、24 内点解整体作废、照片 UNSOLVED。

**修复**：展开前对切平面原点做与 `fitAndVerify` §0.63 相同的迭代。

### 2.4 拟合原点的赤经算术平均跨 0° 接缝（RA-seam bug）

`fitPairs` 用 `pairs.map { it.second.ra }.average()` 取切平面原点。跨 RA=0°/360°
的配对（5087 种子星 RA 345.5°/2.1°/3.3°）算术平均 = 117°，偏出真实中心 120°+
→ `tanXY` 全部 NaN、拟合直接失败。**投票轮能忍**（RANSAC 跳过错样本），
但**打分轮展开是单一 3 对种子，全有或全无** → 直接作废。

**修复**：`fitPairs` 与 `fitAndVerify` 的原点改用**球面向量平均**（unit 向量相加），
跨接缝安全。

## 三、附带的确定性修复（§0.71e）

排查过程中实测到同一代码在不同 JVM 进程间 **SOLVED/UNSOLVED 翻转**
（5057/5087/5092 各出现一次，apod5 在测试 JVM 出现假阳性误报）。根因有两处：

1. **`triKey` 未规范化 HIP 顺序**：同一颗星三角以不同 anchor 顺序各插入一条索引
   记录（r2/r3 相同、hipA/B/C 排列不同），查询合并时同一三角形是 2~3 条
   「并列同分」记录；`take(candidateCap)` 在并列处按 HashMap 遍历序截断
   （每次运行可能不同）→ 投票/打分结果抖动。
2. **候选排序仅 `sortedBy` 接近度**（稳定排序，并列跟随 HashMap 遍历序）。

**修复**：`triKey` 按 hip 升序规范化（同三角形去重，索引同时缩小约 3 倍）；
候选排序加 hipA/hipB/hipC 决胜。**修复后 4/4 次全量回归结果逐位一致。**

## 五、改动清单（`LocalStarMatcher.kt`）

- `voteThresholds`：三档位改「占 top 比例」；**下限钉住绝对标定**（60/25），
  避免亮照片（top 上万）把下限抬到 185/77 整片切掉真星（5057/5087 回归实测）。
- `scoreHypothesis`：切平面原点球面平均 + 迭代到图像中心 + **双 parity 拟合取残差小者**。
- `expandHypothesisPairs`：双 mirror × 原点迭代 × buildWcs 投影（替代手写逆映射）。
- `fitPairs` / `fitAndVerify`：切平面原点改球面向量平均（RA 跨 0° 安全）。
- `triKey`：HIP 升序规范化；候选排序加 hip 决胜（确定性）。
- 新增 `sphericalMeanOf`（任意多星）、`fitResid`（三点拟合残差）、
  调试观测 `debugScoredWinSeed` / `debugExpandDetail`。

## 六、遗留

- 打分轮失败路径仍有 ~3s 时间预算开销（仅投票全败后触发；成功路径不变）。
- `user-nanning3` 原始渲染此前 UNSOLVED 的问题已顺带解决（归因 2.3/2.4）。
- 投票轮本身在 60°+ 宽场的伪三角形污染（§0.62 遗留）未动 —— 本版修复的是
  打分轮的完整链路；投票轮改造仍待内角键实验结论。
