## 2. P2-1 星表扩容

### 2.1 背景与方案

旧星表 919 颗（HIP 索引域 mag≤4.0），大视场广角照片（FOV 60-80°）里亮星稀疏，三角形投票候选不足是边界照片失败的主因。扩容不追求全天空洪泛，而是**在保持索引域不变的前提下把参与匹配的暗星补足**。

生成器 `tools/gen_catalog_hip.py`：
- 解析现有 StarCatalogPart1-8.kt，提取原 919 星（hip>0 且 hip≤120000 的真 HIP）；
- 解析 VizieR BSC5（V/50，Yale Bright Star Catalog 9110 星，fixed-width：HR 1-4、RA J2000 76-90、Vmag 103-107）；
- 增补判定：星在 BSC5 中但没有原星表 → `hip = HR + 120000`（保证全表 HIP 唯一且升序排列，可直接二分查找）。

### 2.2 关键约束：暗星门槛

首轮生成把所有 BSC5 独有星全部混入，触发**索引域反噬**：验证网格（catGrid）与 inliers（countInliers）都是按亮星域 mag 过滤设计的，暗星混入后搜索空间扩大，真实解在投票中的优势被稀释——12 张真机照片的真解从 8 张跌到 2 张，单张耗时升到 50s+。

修复规则（生成器强制）：
- **只收 4.5 < mag ≤ 6.5 的 BSC5 暗星**，BSC5 独有的亮星（≤4.5）一律不收；
- 目录中 mag≤4.5 的星与扩容前完全一致 → catGrid/countInliers/vote 的亮星域语义不变。
- LocalStarMatcher 同时显式恢复两道亮星域护栏：`catGrid()` 跳 mag>4.0、`countInliers()` 跳 mag>4.5（§0.42a）。

### 2.3 组装与校验

- 输出 8 个 part 文件（各 ~1050 星）+ `StarCatalogData.kt` 组装版（stars 依序拼接，`constellationLines` 按 HIP 重映射到新下标，`hipToIndex`/`indexOfHip` 同步生成）；
- 生成器内建三项断言：无缺失星、HIP 值与原表一致、星座连线端点全部落在星表范围内；
- 星座名规避：`StarChartOverlay.constellationLabels` 与 `HistoryStore.nearestConstellationZh` 跳过 `con` 为空的增补星（§0.42b）。

结果：8419 星全量投影/检索的实测代价约 +1.2s/次（JVM 侧），手机预算内可接受。

## 3. P2-2 实时预览认星 MVP

### 3.1 链路设计

CameraScreen 新增 ImageAnalysis（`camera-lifecycle` 绑定）：

```
Preview + ImageCapture + ImageAnalysis(RGBA_8888, 800x600, KEEP_ONLY_LATEST)
   │ 每 5 秒节流（AtomicLong lastAnalyzeMs）
   ▼
RGBA 帧 → bitmapFromRgbaPlanes() 拼装 Bitmap（后台线程）
   ▼
LocalStarMatcher.detectStars(60) + match() 本地求解（无网络）
   ▼
命中 → renderLiveOverlay() 画星座线 → mainHandler.post 给 previewOverlay
   ▼
UI 叠加层 Image + 顶部「已识别：星座名（实时预览）」标签，🛰️/🔭 工具条开关
```

- 节流 5 秒：MVP 期平衡耗电与流畅度；`STRATEGY_KEEP_ONLY_LATEST` 丢帧不阻塞相机；
- 求解失败（无解/低曝光）时清空叠加层，标签回到空白，不打断取景；
- 开关默认开（`livePreview`），右上或工具条一键关闭以省电。

### 3.2 踩坑：CameraX 1.3.x 没有 JPEG 输出

原实现按 `OUTPUT_IMAGE_FORMAT_JPEG` 写，编译报 Unresolved。查证：**JPEG 输出格式是 CameraX 1.4.0 才引入的**（1.3.4 只有 YUV_420_888 / RGBA_8888）。升级 1.4.x 需要 compileSdk 35，且本地 SDK 未装 platform-35，连带风险大。

选型结论：**留在 1.3.4，改用 RGBA_8888 输出**。ImageAnalysis 帧的 planes[0..3] 是 R/G/B/A 单通道，按 rowStride 逐行拼 IntArray → `Bitmap.setPixels`，800x600 每 5 秒一次，后台线程开销可忽略；容量/stride 校验不过就跳过该帧，不崩溃（`bitmapFromRgbaPlanes`）。

### 3.3 叠加绘制

`renderLiveOverlay(frame, wcs)` 在后台线程把帧拷贝为 ARGB_8888，`StarChartOverlay.projectStars/projectLines/constellationLabels` 投影全星表，绘制：
- 星座连线：金色 `0xCCFFC24B` 虚线（14/9 dash），线宽随帧宽自适应；
- 星座名：白色加粗 + 黑色阴影，字号随帧宽自适应（中文名，来自 Constellations.zhName）；
- 旋转：按 `imageInfo.rotationDegrees` 先把帧转正再投影，保证叠加与取景方向一致。

## 5. 已知限制与后续

1. **5 秒节流**：MVP 期防耗电/发热，帧率偏低；后续可做 2s 自适应（求解慢/无解时自动降频）。
2. **弱光无解**：实时帧曝光不足时星点检测失败，与离线识别同样受限于取景亮度；可提示抬 EV 或开闪光补光。
3. **RGBA 拼装是 1.3.x 权宜**：升级 CameraX 1.4.x（需 compileSdk 35 + platform 下载）后可切 JPEG 输出，省掉手动拼装代码。
4. **叠加层遮挡**：预览顶部星座名标签在竖屏下与取景重叠，后续可移动到角落或做成半透明胶囊。
5. 按约定本版本不构建 release，攒批后统一出。
