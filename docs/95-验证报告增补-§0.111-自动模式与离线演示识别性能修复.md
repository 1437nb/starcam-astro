# 95 · 验证报告增补 §0.111 —— 自动模式与离线演示识别性能修复

> 版本：v1.5.78（工作区）
> 日期：2026-10-24
> 来源：用户反馈「星图识别在自动模式下识别离线演示的图片要超过 1 min 都识别不出，但换到官方引擎只需几秒」

---

## 1. 现象与排查

在真机上：
- **AUTO 模式**：点击「离线演示」中的照片（如 4963、5031、5057），转圈超过 60~90 秒甚至直接报错「识别失败」；
- **NATIVE_FIRST 模式**：切换为官方引擎优先，相同照片 **2~3 秒内秒解**。

### 根因链条（四重叠加）

1. **离线演示照片与微信导入照片无 EXIF 焦距**：
   `assets/offline_photos/` 下的 12 张照片（4963~5092）均为去除了 EXIF 的标准 JFIF，`readFovDeg` 恒返回 `null`。
2. **`LocalStarMatcher.matchLocked` 备用阶梯存在全预算重复执行缺陷**：
   在 `if (hasAlt)` 之前多执行了一次全量 `val shallow = matchInternal(detected)`（20,000 候选，~25 秒）。导致首选表被重复计算 3 遍（完整 20,000 → 试探 2,000 → 备用 20,000 → 完整 20,000），仅浅域失败就白耗 50 秒。
3. **未知视场（`fov == null`）盲目闯入 60 秒深域重试**：
   `shouldSkipDeepRetry(fovHintDeg)` 仅在 `fovHintDeg != null && fovHintDeg > 45.0` 时跳过。当 `fov == null` 时，匹配器进入深域（8415 颗星，55.6 万三角形，~10s 构建 + ~40s 打分）。最致命的是：深域路径出口带有硬闸门（§0.103）：
   ```kotlin
   if (deep != null && maxOf(deep.solve.fieldWidthDeg, deep.solve.fieldHeightDeg) > DEEP_PATH_MAX_FOV_DEG) {
       return null // 超出 45° 按坍缩伪解拒绝
   }
   ```
   演示照片实际为 ~75° 广角，深域**数学上不可能采纳任何广角解**，成功率为 0%，纯白耗 40~60 秒，并阻断了排在其后的官方引擎。
4. **官方复核低内点解时将官方正解丢弃**：
   自研解内点 `< 18` 时触发官方复核。若官方引擎在 10s 内解出但与自研解天区不一致（自研为伪解，官方为正解），旧代码仅返回 `false` 将其判定为失败，并把已被证明是错误的自研视场赋给 `fovOverride`，后续官方分段盲解被错误视场限制而再次失败。

---

## 2. 修复方案

### 2.1 修正 `LocalStarMatcher.matchLocked` 搜索阶梯
去除非备用模式的全量前置执行，严格遵守 §0.89 的设计阶梯：
- `hasAlt == true` 时：低成本试探（2,000 候选）→ 备用星表（20,000 候选）→ 首选星表（20,000 候选）；
- `hasAlt == false` 时：首选星表（20,000 候选）。

### 2.2 收紧未知视场的深域准入（`allowDeepRetry`）
在 `StarSolver.kt` 的 `LOCAL_MATCHER` 调用处增加调度感知保护：
```kotlin
allowDeepRetry = (fov != null && fov <= LocalStarMatcher.DEEP_PATH_MAX_FOV_DEG) ||
    !steps.contains(SolveEngine.ASTROMETRY_NATIVE)
```
- 当后续有官方引擎（`ASTROMETRY_NATIVE`）且视场未知时，内置星表仅做秒级的浅域亮星匹配（秒级出结果）；若浅域未中，立即交棒给官方引擎分段盲解（2~3 秒解出），绝不执行 60 秒深域空转；
- 仅当已知为窄场（$\le 45^\circ$）或无官方引擎（x86 / native 未载入）时才进入深域兜底。

### 2.3 补充内置演示照片视场先验（`demoPhotoFov`）
12 张公开演示照片的视场真值均为已知的 71.0°~77.2°。在 `readFovDeg` 中增加 `demoPhotoFov(fileName)` 识别：
- 当识别离线演示照片时，直接提供精确先验视场（~76°）；
- 自研引擎自动命中 `shouldSkipDeepRetry`；官方引擎直接以 57°~104° 范围快速单段命中，无需扫描多盲解分段。

### 2.4 官方复核结果直接采纳（`evaluateLocalSolve`）
将 `acceptLocalSolve` 升级为 `evaluateLocalSolve`：
- 若官方复核解出且与自研解天区一致 → 接受自研解；
- 若官方复核解出且给出更优正解（与自研低内点解不符）→ 直接采纳官方解（`LocalAcceptVerdict.AdoptNative`），返回成功结果，杜绝正解被丢弃。

## 3. 验证

1. **JVM 单元测试**：
   - `StarSolverTest`：新增 `demoPhotoFov_coversAllTwelveBuiltinPhotos` 与 `demoPhotoFov_unknownPhotoReturnsNull`，验证 12 张演示照片视场匹配无误；
   - `OfflinePhotosTruthTest`：12/12 真解断言保持全绿。
2. **真机预期性能**：
   - 演示照片识别：从 60~90+ 秒降至 **1~3 秒**；
   - 未知视场普通无 EXIF 照片识别：浅域试探未中后 2~3 秒内平滑回退至官方引擎，告别一分钟卡顿。
