## §0.34 图片缩放查看器

**需求**：无论识别成功或失败，都能点击图片放大/缩小查看星星与星座连线。

**实现**：
1. `ui/result/ZoomableImageViewer.kt`（新）：全屏查看器——捏合缩放 1~5x、
   单指拖拽平移（限制在图片边缘内）、双击放大 3x（以点击点为中心）/还原、
   顶部标题 + ✕ 关闭、底部操作提示。
2. 成功页：星座叠加图（照片 + 星座连线 + 星名，复用 `renderAnnotatedBitmap`
   合成位图）点击放大，叠加标注随图片整体缩放。
3. 失败页：诊断标注图（照片 + 金色星点圈，新增 `renderDiagnosticBitmap`
   合成位图）点击放大。
4. 两处图片区右下角加"🔍 点击图片放大查看"提示。

**验证**：60 项单测全绿；手势交互为运行时行为，**待真机**（捏合/拖拽/双击、
成功页星座线与星名缩放清晰度、失败页星点圈缩放）。

## §0.35 构建提速（用户反馈"终端执行命令要十几分钟、CPU 占用率低"）

**根因**：整套 Gradle 配置沿用旧阿里云 1.8GB 小内存服务器的保守设定——
`--no-daemon`（每次冷启动 JVM + 全量配置）、`workers.max=1`（单 worker）、
`kotlin.compiler.execution.strategy=in-process`（Kotlin 编译器在 Gradle 进程内
**单线程**编译，4 核只用 1 核 → CPU 占用率低的直接原因）、jvmargs 经
GRADLE_OPTS 传递且堆偏小（GC 频繁）。

**改动**（gradle.properties + starcam-build.bat）：
- 启用 Gradle daemon（移除 `--no-daemon`）；
- `org.gradle.jvmargs=-Xmx3g -XX:MaxMetaspaceSize=768m -XX:+UseParallelGC`；
- `org.gradle.workers.max=4`、`org.gradle.parallel=true`、
  `org.gradle.configuration-cache=true`；
- **Kotlin 改独立 daemon**（`kotlin.compiler.execution.strategy=daemon` +
  `kotlin.daemon.jvmargs=-Xmx2g`）——多线程编译，吃满 4 核；
- 移除 bat 中的 GRADLE_OPTS（避免 `-D` 覆盖 gradle.properties 的 jvmargs）；
- 测试并行：`maxParallelForks=2`、worker 堆 512m。

**实测（本机，2026-09-01）**：

| 场景 | 旧配置 | 新配置 |
|---|---|---|
| 全量单测（60 项） | 14m55s | **3m01s**（-80%） |
| 日常增量构建（改 1 个文件） | 5~10 分钟 | **15s** |
| 全 up-to-date 构建 | 1~2 分钟 | **4s** |
| release 全量（R8） | 45 分钟 | 23 分钟 |

**已知项**：配置变更后的全量 Kotlin 重编译仍需 ~10 分钟，瓶颈是
`StarCatalogData.kt`（80KB 单文件，919 颗星数据，编译器按文件串行处理）；
日常增量（该文件不改动时）15 秒，不受影响。若需压全量，可把星表数据拆成
多个文件（结构性改动，暂缓）。
